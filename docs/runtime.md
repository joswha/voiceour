# Runtime contract

How a dictation runs, what it may touch and store, and how the app is run locally. [AGENTS.md](../AGENTS.md) maps the other contracts; [`.omp/RULES.md`](../.omp/RULES.md) holds the invariants every change keeps.

## Runtime flow

```text
idle -> checkingPermissions -> recording -> finalizingAudio -> transcribing -> cleaning
cleaning -> readyToInsert -> pasteAttempted | copiedOnly | insertFailed -> idle
cleaning -> noteSaved -> idle
```

`error` and `cancelled` also return to `idle`. `noteSaved` (“Note saved”) is terminal: neither active nor critical.

- Capture target: snapshot before recording; record-start label only. Delivery target: snapshot immediately before persistence/insertion; determines delivery. Agent binding captures Tern's focused pane right after the delivery snapshot and resolves it after the paste; it NEVER delays or changes delivery ([Agent session binding](#agent-session-binding)).
- Intent: `start(intent:)` sets `captureIntent` (`CaptureIntent`: `.deliver` or `.note`) for the session and every end of the session resets it to `.deliver`; `startNote()` is `start(intent: .note)`. The hotkey, the island and the harness start `.deliver`; the menu's Take a Note row and the Journal's Notes lens start `.note`. `lastSavedNoteID` names the note the last session saved; the next start clears it.
- Note branch (`TranscriptProcessingPipeline.swift`): after the text stages and the empty-transcript check, the delivery target is snapshotted as for any dictation; a `.note` session skips `readyToInsert`. A `.note` session saves its final text whatever the target; a `.deliver` session becomes a note only when the target is not secure and `NotePrefix.strip` matches ([text-pipeline.md › Spoken note command](text-pipeline.md#spoken-note-command)), saving the stripped text. `recordNote(text:captureSeconds:)` commits it; whitespace-only text → `cancelled`. Then `completeFirstRun()`, the note's session link ([Agent session binding](#agent-session-binding)), `noteSaved`, `idle`.
- A note NEVER writes the pasteboard, posts Cmd-V, writes a History row or folds the ledger, and computes no learned suggestions. The menu reports it from `lastSavedNoteID`; the island shows no outcome pose and announces nothing; the end cue plays as for any dictation.
- First run: a saved note completes onboarding (`completeFirstRun()`), as a delivery does.
- Fn/Globe toggles on solitary release. Shift, Control, Option, Command, Caps Lock, or another key during the hold disarms it. Toggle during recording stops; during `checkingPermissions` cancels; during finalizing/transcribing/cleaning/delivery does nothing.
- Trusted event tap consumes Globe assigned-action keycode 179, the toggling Fn release, and active-session unmodified Escape keyDown/repeats/keyUp. Passive monitors never suppress and MUST ignore keycode 179. A 2 s watchdog promotes to the tap when trust appears; prompt at most once/process, never mid-session.
- MUST recreate `HotkeyEventRouter` whenever the tap is rebuilt or torn down.
- Escape/island Cancel discards checking-permission, recording, finalizing, or transcribing work. Cancellation after the pasteboard write reports copy-only, not failure. A note is saved in the main-actor turn that ends its session, so a cancel before that turn saves nothing.
- Real start MUST reject an unready model with `model_not_installed` before prompting for Microphone; request Microphone only if undetermined. Fake skips both gates.
- Stop MUST finalize one WAV and decode once. No in-progress ASR requests or recording-length cap. No input signal within 6 s → stop and report no audio.
- MUST reject stale recording/decode/suggestion work using `AsyncGenerationGate` and cancellation checks.
- Capture: 16 kHz, mono, 16-bit WAV in `$TMPDIR/voiceour/`. Startup failure removes it. Once finalization starts, the pipeline alone owns discard. Launch scavenging removes recordings older than one hour.
- MUST latch runtime errors, device disconnects, conversion failures, WAV-write failures. Finalization drains the converter, closes WAV, rejects latched failures, zero written frames, or all-zero recordings. Liveness MUST scan every channel, including interleaved Int16/Int32.
- `AVCaptureSession` start/stop MUST share serial `com.voiceour.capture-session`; never main actor. Telemetry analysis also runs off-main.
- `CoreAudioInputDevice.preferredCaptureUID`: connected explicit selection > system default. Bluetooth/BLE default + open lid → built-in microphone. Unresolved selection → fallback, not capture failure.
- Before ASR: non-synthetic capture with `snrDB < DictationPolicy.minimumCaptureSNRDB` (6 dB) → `cancelled`. Missing telemetry or synthetic capture proceeds.
- Compile `VocabularyCompiler` snapshot once after finalization, before ASR. Apply text stages once after ASR; snapshot delivery target next.
- Failures MUST use `UserFacingDictationFailure`: title, plain cause, retryability, recovery destination. Raw codes MUST NOT be primary UI text.
- Wire `SidecarASRClientError.protocolError` preserves its code/detail. Local timeout → `timeout`; launch/no greeting/process exit/pipe write → `backend_unavailable`; incompatible greeting/unexpected response → `incompatible_protocol`. Preserve the public client error enum.
- Muting applies to `granite`, never `fake`. Start cue before mute; begin restore immediately when capture ends, without awaiting the 120 ms fade; end cue after restore.
- Mute ownership is durable and device-UID-bound. Unresolved UID → retain ownership and refuse another mute. Clear only after a real restore attempt. Disk-loaded/interrupted fades restore partial volumes; completed live fades retain the user-adjusted-volume check.
- A duplicate bundled instance MUST quit at launch. Quit MUST discard active work and restore audio before exit.

## Privacy and insertion safety

- `InsertionSafetyPolicy` alone maps class to disposition. Only `.normalText` may synthesize Cmd-V; terminal, code-editor, secure, unknown-risky remain copy-only. NEVER add a bypass setting.
- `SafetyClassifier` precedence: secure input > secure AX role/subrole > missing bundle id (unknown-risky) > known secure/terminal/editor bundle > unavailable AX inspection (unknown-risky) > normal text.
- Preserve Ghostty `com.mitchellh.ghostty` as terminal, Zed `dev.zed.Zed` and `com.jetbrains.` prefixes as editors.
- `kAXErrorNoValue` means no focused element; classify by bundle. Readable element with nil role/subrole may be normal text after secure checks. Other AX failures MUST fail closed.
- The paste path (a `.normalText` target with Cmd-V permission) MUST recheck the snapshot — bundle id, app name, pid, safety class, secure-input flag (`TargetTracking.stillMatches`, whole-snapshot equality) — before the clipboard write AND after it, before Cmd-V: a mismatch before the write → copy-only `target_changed_before_copy`, after it → copy-only `target_changed_after_copy`. A copy-only class and a refused paste permission write the clipboard with no recheck, since no keystroke follows. The snapshot holds no window or element, so focus moved to another field of the same app and class passes the recheck.
- Terminal/unknown-risky copies strip exactly one trailing newline.
- Secure delivery MUST use concealed, host-only copy and skip both `recent-sessions.json` and ledger. Other copy-only output is plain string and never cleared.
- Ordinary paste attempts use the transient marker. Only a posted Cmd-V schedules clearing: 1.5 s later, clear only if pasteboard change count still matches.
- MUST publish transcript + markers as one `NSPasteboardItem`. `GeneralPasteboard.copy == nil` → `pasteboard_write_failed`; NEVER post Cmd-V, schedule clearing, confirm copying, or announce delivery after failure.
- Clipboard access writes only the transcript; NEVER read/save/restore previous clipboard content. AX reads focus only; NEVER mutate text through AX.
- MUST remove temporary audio after success, cancellation, error, and stale-file scavenging.

## Persistence

- Support directory: `~/Library/Application Support/Voiceour/`, overridden verbatim by `VOICEOUR_SUPPORT_DIR`. Files: `settings.json`, `recent-sessions.json`, `dictation-activity.json`; mute ownership: `mute-owned.flag`; the TypeSafe key file `typesafe.key` ([Local-first and network policy](#local-first-and-network-policy)); the memory folder `memory/`, whose layout and rules belong to [memory.md](memory.md).
- `memory/agents/` is read-only for Voiceour: agents write the notes there, `refreshAgentNotes()` reads them off the main actor and the Journal shows them ([memory.md › Agent access](memory.md#agent-access)). NEVER write, edit, move or delete a file under it; only Clear Memory, or Clear History and Memory, removes it, with the whole folder.
- Settings/history/ledger/memory writes MUST be owner-only, atomic per file, off-main, on one detached FIFO tail. No cross-file transaction. History write failure MUST report “Dictation history could not be saved.” without blocking delivery or later saves.
- Unreadable settings/history/ledger → quarantine as `<name>.corrupt-<ISO8601>` and report reset + filename. Island values NEVER trigger it: `Settings.island` falls back per field ([Recording island](recording-island.md)). NEVER suppress write failures.
- History: one file, newest-first, max 500. Fold ledger from the same journaled row in the same main-actor turn; enqueue both snapshots. Secure target → neither; every other disposition → both. Home and first-run checks read both records.
- Memory ([memory.md › Lifecycle](memory.md#lifecycle)): with `Settings.memoryEnabled` on, the same journaled row folds into memory in that main-actor turn too. Tail order per dictation: History snapshot, ledger snapshot, memory commit (`commitMemory`). Delivery NEVER waits for the memory write. Secure target → no memory entry either.
- Notes are memory-only: `recordNote(text:captureSeconds:)` (`MemoryJournal.swift`) commits one `.note` entry with no app through `commitMemory` on the same tail, whatever `Settings.memoryEnabled` says, and never touches `recent-sessions.json` or the ledger. A note goes only when memory loses it: Delete Entry…, Clear Memory, or Clear History and Memory; Clear History alone keeps it.
- Delete and clear: deleting a transcript removes the History row and the memory entry with its id, whichever exist, so a reading row's Delete Entry… removes an entry only memory holds. Clear History leaves memory alone; its dialog's Clear History and Memory erases both. Clear Memory removes the whole folder, `agents/` included, behind every write already queued; both refuse while the app is terminating.
- Memory failures, NEVER suppressed: “Memory could not be saved.” (a write failed; later writes still run), “Memory could not be erased.” (Clear Memory failed), “Memory could not be read — kept as <file>.” (an unreadable month file, `topics.json` or `entries/` set aside at launch; “Memory could not be read and could not be set aside.” when the move failed).
- Sorting ([memory.md › Sorting](memory.md#sorting)): `Settings.organizerEnabled` (`organizer_enabled`, off by default, “Sort entries with Jev” in Settings ▸ Memory) turns label requests on; it does nothing without a key. A label lands through `commitMemory` on the same tail as any memory change. Delivery, state changes and the next dictation NEVER wait for a label.
- `typesafe.key`: written only by Settings ▸ Memory ▸ Save Key (`saveTypeSafeKey`), owner-only (0600) and atomic like every other support file; Remove Key, or saving a blank key, deletes it. Clear History and Clear Memory leave it alone. A failed write or removal returns false and the key row says “The key file could not be changed on this Mac.”
- Agent session bindings (`RecentSession.agentSession`): nil = unbound. Attached once per row by [Agent session binding](#agent-session-binding); later title, resumability and send updates go through the same journal FIFO and are mirrored onto the memory entry with the same id. `send`: nil = pending, `.sent(sentAt:text:)`, or `.notSent` once the 30-minute send window closes and the bound session's records were read without the dictation; a session that cannot be read stays pending. A malformed binding decodes as nil and an unknown send status as pending; neither quarantines History. The retired `agentLink` field and `agent_session_linking_enabled` key are neither read nor written, and no row is ever backfilled. Turning `Settings.agentSessionBindingEnabled` off strips every binding and every miss and persists History without them, and strips `thread` and `unlinked` from every memory entry. Bindings and misses never enter the ledger.
- Link misses (`RecentSession.unlinked`, JSON key `unlinked`, the `AgentLinkMiss` raw value): set once on an unbound row by a missed link ([Agent session binding](#agent-session-binding)); nil = linked, not attempted, or unknown, rows saved before misses were recorded included. Encoded only when set; an unknown or malformed value decodes as nil and NEVER fails the row or quarantines History. A row NEVER holds both a binding and a miss. Mirrored onto the memory entry with the same id ([memory.md › Entries](memory.md#entries)).
- Ledger: sessions/words/seconds by local day and destination bundle id; totals, active days, longest streak; no text/session ids. Prune day buckets >400 days before the recorded day, preserving totals, active-day count, and longest streak. Empty ledger → remove file. Retired `dictation-stats.json` is swept at launch.
- App buckets MUST NOT be capped/pruned. Keep sessions/words/seconds, last non-nil display name, latest day key.
- Missing ledger → seed once from remaining History. Missing `captureMs` contributes words and zero seconds. `totalSessions > 0 && apps.isEmpty` → seed app buckets only; NEVER recount totals.
- Clear History erases History + ledger, and memory only when Clear History and Memory is chosen. Clear Vocabulary removes user terms and restores surviving bundled terms' shipped surfaces.
- Diagnostics MUST include build/backend/model/health/permissions/microphone/session-count/agent-session-binding on-off, `keep dictations in memory: on|off`, `memory entries: <count>`, `sort entries with jev: on|off`, `typesafe key: environment|key file|none`, and storage paths with a `memory:` line. NEVER the key, transcript text, topic names, agent session ids or session paths.

## Local-first and network policy

- Compiled network destinations, exactly two: Granite's pinned host/repository/revision and digest ([asr.md](asr.md)), and `TypeSafeOrganizer.endpoint`, `POST https://api.typesafe.ai/v1/systemone`. NEVER telemetry, crash reporting, accounts, update checks, arbitrary URLs, a model that writes or rewrites text, or a second recognizer beyond `granite`.
- Network code: only `ASRSidecarCore` (the model download) and `VoiceOrganizer` (`Sources/VoiceOrganizer/TypeSafeOrganizer.swift`) may hold it; `.omp/rules/local-only-network.md` blocks it in `VoiceCore`, `VoiceMac`, `Voiceour` and `VoiceourASR`. The app reaches the organizer only through `EntryOrganizing`; `live()` injects `TypeSafeOrganizer`, and every other coordinator, test and harness fixture defaults to `NoEntryOrganizing`, which sends nothing.
- Label request gates, all REQUIRED: `Settings.organizerEnabled` on, a key from `TypeSafeKeySource`, and one of three causes: a dictation folding into memory, a note being saved, or a Sort Entries run ([memory.md › Sorting](memory.md#sorting)). Turning the switch off, Clear Memory and quit cancel every request in flight.
- A label request holds the model id (`OrganizerPolicy.model`, `jev-1.14.0`), the entry's text cut to its first 8,000 characters (`OrganizerPolicy.maximumTextCharacters`; memory keeps the whole text), fixed questions and rubrics for the kind and keep labels, and, when topics exist, the first 254 topics' ids, names and summaries plus `none`. Headers: `Authorization: Bearer <key>`, JSON `Accept` and `Content-Type`, `User-Agent: Voiceour`. NEVER agent session data (agent, session id, title, project, directory, send state), the app, a file path, audio, raw recognizer text, timings or another entry. The reply is labels only (`JudgmentReply.label`): a kind, a topic id from the offered list or none, a keep score, with confidences; no text it carries reaches memory.
- Transport: `TypeSafeOrganizer.makeSession()` is ephemeral, with no cookie storage, no URL cache, no credential storage, `waitsForConnectivity` off and a 10 s request timeout. At most three attempts per entry: a connection that never formed or dropped, or HTTP 408, 429 or 5xx, is retried after 0.5 s and then 1.5 s, or after a delay-seconds `Retry-After` capped at 5 s; a timeout, a cancellation, any other status and an undecodable reply end the request with no label. The endpoint is fixed: no setting, environment variable or argument changes it, and every redirect is refused (`RedirectRefusal`), so a 3xx reply ends the request with no label and nothing is sent to a second host.
- The `organizer` log category carries HTTP statuses and failure kinds only; NEVER the key, the entry text, topics or the reply.
- Agent session binding reads, only while it is on and only on this Mac: the decoded focus, window-client, pane-id, identity-method and `omp_session_file` fields of `tern` output; the process-table entry, executable path and open file paths of the pane's foreground process and of processes on its terminal; `~/.omp/agent/terminal-sessions/<tty>`; the bound omp session file's head and appended records; `~/.claude/sessions/<pid>.json` records; `~/.claude/history.jsonl` records of the bound session id; title records of `~/.claude/projects/*/<sessionId>.jsonl`. NEVER written to, uploaded, logged, or used for anything but binding History rows, linking notes, and mirroring those bindings into memory: a bound row's agent, session id, title, working directory, resumability and send state are copied into its memory entry and its Markdown pages ([memory.md](memory.md)), and a linked note's are the same fields without a send state; nothing else from the session files reaches memory. Turning binding off strips every memory entry's session too.
- Sidecar env allowlist: `PATH`, `HOME`, `TMPDIR`, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` + lowercase forms, `SSL_CERT_FILE`, `VOICEOUR_*`. NEVER inherit full parent env, so `TYPESAFE_API_KEY` never reaches the sidecar. Always write `VOICEOUR_ASR_BACKEND`, `VOICEOUR_PRELOAD=1`.
- Credential: one, the TypeSafe key. `TypeSafeKeySource` reads `TYPESAFE_API_KEY`, else `typesafe.key` in the support directory; each value is trimmed and a blank one falls through. Settings shows only where the key comes from, never the key; it is never logged, put in Diagnostics, an error, or a request other than the label request's `Authorization` header. No other credential UI, credential environment contract, configurable base URL, secret store, or keychain item. `Resources/Voiceour.entitlements`: audio-input only; no provisioning profile. Data-protection Keychain is unavailable: `SecItemAdd` returns `errSecMissingEntitlement` (-34018); ad-hoc `keychain-access-groups` fails AMFI. NEVER add a feature depending on it.

## Agent session binding

Binds a History row, or links a note, to the omp or Claude Code session running in Tern's focused pane, exactly or not at all; NEVER infer a session from text similarity across sessions. Coordinator: `AgentSessionLinking.swift` (rows) and `MemoryJournal.swift` (notes). Ports: `AgentSessionResolving` (`LiveAgentSessionResolver`) and `AgentSessionReading` (`AgentSessionFileReader`); the send check is `AgentPromptSendMatcher`.

- Gates, all REQUIRED: `Settings.agentSessionBindingEnabled` (`agent_session_binding_enabled`, off by default); the History row exists; outcome `.pasteAttempted`; delivery target `.normalText` with bundle id `so.stencil.tern`. Tern is the only host; omp and Claude Code are the only agents; Codex is never bound. Rows delivered while the setting was off stay unbound and record no miss.
- Timing: `capture(target:)` starts off-main right after the delivery snapshot, which is also `boundAt`, and records Tern's focused pane and foreground pid. After the row's outcome is written, `resolve(target:before:)` runs off-main and binds only when the same pane and the same foreground pid have focus after the paste. Neither delays delivery, state changes or the next dictation. A capture never waits: it reads focus before the paste or reports `busy`. One capture or resolve holds the resolver's lane at a time, and a call that finds it taken returns `busy` at once; after a `tern` timeout, every call for the next 10 s returns `tern_timeout` without running `tern`.
- Resolution, any failure → no binding and one miss ([reasons](#link-miss-reasons)): exactly one window client, all its identity hops `local`; the shown session's shown tab's focused block equals `tern process @focused`'s pane and the captured pane; the pane's hops all `local`; Tern's focused AX element (250 ms messaging timeout) has role `AXTextArea` and title `Terminal input` or `Terminal`; the foreground process is alive, same uid, has a controlling tty, leads its tty's foreground process group, and shares the pane shell's tty. The agent comes from the executable path and name only.
- omp identity: Tern's `omp_session_file` for the pane and the foreground process's open `~/.omp/agent/sessions/<dir>/<ISO>Z_<uuid>.jsonl` (depth exactly one) MUST name the same standardized path when both are present. Only when both are absent, line 2 of `~/.omp/agent/terminal-sessions/<tty>` counts, if its mtime ≥ the process start and no other live omp process shares the tty. The session id is the filename's UUID; a not-yet-written file still binds, unresumable until it exists.
- Claude Code identity: `~/.claude/sessions/<pid>.json` whose `pid` matches and whose `procStart` is within ±1 s of the kernel start time; a `parkedJobId` follows to exactly one live, same-uid, non-spare `bg` record with that `jobId` and a matching `procStart`. Title: `name` unless `nameSource` is `derived`, else the last `custom-title`/`ai-title` record in the last 256 KB of `~/.claude/projects/*/<sessionId>.jsonl`.
- `tern` CLI: runs only from `Contents/MacOS/tern` of the `so.stencil.tern` process being pasted into, after both that running code and that file satisfy `identifier "so.stencil.tern" and anchor apple generic and certificate leaf[subject.OU] = "VTLHGQC72S"` (the file check is cached by device, inode, size and mtime). Only `process @focused --json` and `inspect --json`: argv only, environment exactly `HOME` and `PATH=/usr/bin:/bin`, stdin/stderr `/dev/null`, stdout drained concurrently and capped at 1 MiB, 1 s deadline → SIGTERM → 100 ms bounded join → SIGKILL; NEVER `waitUntilExit()`. A failed signature check, non-zero exit, cap overrun or undecodable report → `tern_unavailable`; a timeout → `tern_timeout`; neither binds. Decode only the fields the checks need; NEVER keep argv, cwd, titles or raw output, and zero the output buffer after decoding.
- Process inspection: process-table entry (uid, process group, terminal foreground group, tty, start time, name), executable path and open file paths only. NEVER read another process's argv or environment (`KERN_PROCARGS`, `KERN_PROCARGS2`, `KERN_PROCENV`).
- File access: open only canonical (`realpath`) paths under `~/.omp/agent/` or `~/.claude/`; an omp session file elsewhere binds by its filename id and nothing is read from it. Session heads ≤ 64 KB. NEVER read Claude Code's `.key` files or open or stat a working directory; working directories stay strings.
- Ownership: the coordinator owns each row's binding task (`agentBindingTasks`, identity-checked removal) and one refresh task. Binding uses `currentToken(.agentLinking)`, NEVER `begin`. Quit cancels every task; Clear History and turning the setting off invalidate `.agentLinking` and cancel them; deleting a row cancels its task; cancelling a later dictation touches none. Cancellation terminates in-flight `tern` children. A binding attaches once through the journal FIFO only while the token is current, the setting is on, termination has not begun, and the row exists unbound.
- Misses (`AgentLinkMiss`, `Sources/VoiceCore/AgentSessionBinding.swift`): a row that passed the gates and was not bound records exactly one reason, the first failure met: a failed capture's (the resolve then never runs), else the failed resolve's. Each call checks the lane, then the quiet period, the signature and the `tern` runs; a resolve then checks in the order Resolution lists, then the agent's records. `capture(target:)` and `resolve(target:before:)` return `Result<_, AgentLinkMiss>`; `NoAgentSessionResolving` answers `tern_unavailable`. A miss lands under the attach gates (token current, setting on, not terminating, row exists unbound): it sets `RecentSession.unlinked`, enqueues one journal snapshot, and is mirrored through `commitMemory` onto the memory entry with that id when memory holds it. A cancelled task writes nothing, so a quit mid-resolve, a deleted row, Clear History and turning the setting off leave no miss. NEVER record one for a copy-only delivery, another app, or a row delivered while the setting was off. Turning the setting off clears every miss with the bindings ([Persistence](#persistence)).
- Note link (`startNoteSessionLink`, `applyNoteSessionLink`): gates, all REQUIRED: `agentSessionBindingApplies(to:)` on the note's delivery-target snapshot (setting on, `.normalText` target with bundle id `so.stencil.tern`) and the note in memory with no `thread`; no outcome gate, since a note is delivered nowhere. The capture starts right after the snapshot, as for a paste; once the note is saved, `resolve(target:before:)` runs once off-main. An exact answer sets the memory entry's `thread` (`JournalThreadRef(_ resolved:)`, `sent` nil) through `commitMemory`; a failed capture or resolve sets the entry's `unlinked` to its miss through `commitMemory` instead, and the note stays without a thread for good. Ownership matches a row binding: the task lives in `agentBindingTasks` under the note's id, observes `currentToken(.agentLinking)`, and lands only while the token is current, the setting is on, termination has not begun and the note exists with no thread. Quit and turning the setting off cancel it like a row's task; Clear Memory cancels every note's task. A note has no send check: nothing refreshes it, and its `thread.sent` stays nil.
- Send check: `refreshAgentSessions()` runs single-flight with a rerun flag, on History appear, row-set change, selection, and after a binding attaches. Candidates: bound rows with `send == nil`, or untitled or unresumable rows inside the send window. Off-main, `AgentSessionReading` reads only the bound session's records — the omp session file's user messages, or `~/.claude/history.jsonl` lines of the bound id decoding only `sessionId`, `timestamp`, `display`, `pastedContents` — starting 256 KiB before `promptLogOffset`, which is measured when the binding resolves, a moment after the paste; when the file shrank, the offset is not at a line start, or there is none, it reads the last 16 MiB instead. It reads at most 16 MiB, NEVER parses a partial line, and keeps only prompts sent from 1 s before `boundAt`: `boundAt` precedes the paste, so an earlier matching prompt is another prompt with the same words. A Claude Code title is the live registry `name` unless `nameSource` is `derived`, else the transcript's last `custom-title`/`ai-title`. `AgentPromptSendMatcher` takes the earliest prompt within 30 minutes of `boundAt` whose tokens align with the dictation at score ≥ 0.6, or, under three dictation tokens, equal the prompt's leading or trailing tokens → `.sent`, storing the matching part of the prompt only when it differs from the delivered text after whitespace collapse; none once the window closes → `.notSent`; a session that cannot be read stays pending. Results apply under the attach gates, change only differing fields, and write the journal once per pass. Changing matcher thresholds requires measured counts on real History.

### Link miss reasons

Closed and many-to-one. JSON holds the raw value; UI text is always `Not linked. ` followed by the sentence, NEVER the raw value. No reason is derived from argv, cwd, titles, paths or Tern's output, and no sentence is built from them.

| raw value | when | sentence |
| --- | --- | --- |
| `busy` | another capture or resolve held the resolver's lane | `Voiceour was still linking an earlier dictation.` |
| `tern_timeout` | a `tern` run hit its 1 s deadline, or the call came within 10 s of one that did | `Tern did not answer in time.` |
| `tern_unavailable` | Tern or its `tern` file failed the signature check, a run failed or overran its cap, or a report could not be decoded | `Tern's own report could not be read.` |
| `focus_moved` | the pane or foreground pid differs from the capture, the shown block is not the pane, or Tern's AX focus is not the terminal input | `The focus in Tern moved during the paste.` |
| `several_windows` | Tern reports other than exactly one window client | `Tern had more than one window open.` |
| `remote` | a window client's or the pane's identity hop is not `local` | `The pane runs on another computer.` |
| `no_agent` | the foreground program is none of omp, Claude Code and Codex, or a process check fails | `The pane was not running omp or Claude Code.` |
| `codex` | the foreground program is Codex | `Codex sessions are not linked.` |
| `session_unconfirmed` | the agent is known but its records do not name exactly one session: sources disagree, a record is missing, the start time does not match, the id is malformed, or several candidates remain | `The agent's own records did not name one session.` |

## Environment seams

Overrides apply to one run, never persist settings.

| variable | reader / contract |
| --- | --- |
| `VOICEOUR_ASR_BACKEND` | App: `--asr-backend` > env > persisted setting (any id, `--debug` launches only) > `granite`; invalid values fall through to the next source. Values `granite`, `fake`. Standalone sidecar default: `fake`; `voiceour-asr --prove` runs Granite only. |
| `VOICEOUR_MODEL_CACHE` | Sidecar, Granite: caller-owned single directory; no subdirectory or pruning. |
| `VOICEOUR_SUPPORT_DIR` | App: exact support-directory replacement. |
| `VOICEOUR_PRELOAD` | Sidecar: `1` starts preload; app always sets it. |
| `VOICEOUR_IDLE_UNLOAD_MS` | Sidecar: default 1,800,000 ms; ≤0 disables idle release. |
| `VOICEOUR_ASR_LOG` | Sidecar, Granite native logs: `debug`, `warn`, `error`, `none`; default info. |
| `VOICEOUR_FAKE_DELAY_MS` | Fake backend: transcription delay for cancellation tests. |
| `VOICEOUR_GRANITE_INTEGRATION`, `VOICEOUR_CAPTURE_INTEGRATION` | Tests: set `1` to opt into real Granite model / real microphone suites. |
| `VOICEOUR_GRANITE_MODEL` | Granite integration tests: explicit GGUF path; default the Granite cache. |

## macOS permissions and signing

- Microphone: real capture only, requested at first recording. Accessibility: active suppression + synthetic paste; gate `CGPreflightPostEventAccess()` or `AXIsProcessTrusted()`, prompted at most once/process. Without trust: passive observation + copy-only. NEVER request Input Monitoring or its entitlement.
- Stable signing is REQUIRED for repeatable TCC checks; ad-hoc rebuilds may change identity.
- Bundling precedence: explicit `VOICEOUR_CODESIGN_IDENTITY` / `VOICEOUR_CODESIGN_KEYCHAIN` > `.env` pins > `voiceour-dev` in `~/Library/Keychains/voiceour-dev.keychain-db` > ad-hoc `-` with warning. Explicit identity bypasses local pins. Ad-hoc override: `VOICEOUR_CODESIGN_IDENTITY=- make bundle`.
- Locked development keychain → owner unlocks it. NEVER delete/reset a keychain to build; NEVER commit signing output. Identity changes may require fresh Microphone/Accessibility grants.
- Development bundles lack hardened runtime; `scripts/sign_notarize.sh` enables/verifies it on app AND helper.
- Release qualification MUST cover signed helper, hardened runtime, entitlements, clean-account permissions, and [manual delivery matrix](../README.md#verification).

## Fast iteration runtime

- Behavior/resource change → rebuild and relaunch the exercised surface. Fake path for deterministic coordinator/menu/window checks; signed real bundle for microphone/acquisition/hotkey/insertion/entitlement/signature/helper/material checks. Respect interruption consent.
- `make run`: rebuild on `Package.swift`, `scripts/bundle.sh`, `Sources/`, `Resources/`, `Vendor/` changes; stop existing instance; launch. Launching over a live instance verifies the OLD binary: the new duplicate quits. `.env`/signing changes require `make bundle` explicitly.
- `make dev`: unbundled debug executable, fake unless `VOICEOUR_ASR_BACKEND` set; stops nothing.
- `make stop`/`make status` match process name `Voiceour`. Sidecar exits after stdin EOF + bounded shutdown; check lingering `voiceour-asr` when relevant. MUST verify intended PID/bundle with `make status`.
- `make run`/`make dev` source root `.env` and export every key; bundling reads signing pins. `make run` forwards `VOICEOUR_ASR_BACKEND`, `VOICEOUR_SUPPORT_DIR` and `TYPESAFE_API_KEY` via `open --env`, each only when set; MUST add forwarding for new app-read env names, NEVER assume LaunchServices inheritance.
- Run/dev flags use `ARGS`, e.g. `make run ARGS="--debug --show-console"`. Supported: `--debug`, `--show-console`, `--console-section=<home|glossary|history|settings>` (`history` opens the Journal tab), `--no-activate`, `--asr-backend <id>`, `--self-test`; `--ui-harness` only with `-DUI_HARNESS`.
- Logs: subsystem `com.voiceour.app`, categories `hotkey`, `audio`, `model` (retired model-cache sweep failures), `organizer` (label request statuses and failure kinds). `stop-path` signposts require Instruments/`xctrace`.

# Native UI contract

The console window and its tabs, the component kit they are built from, and the visual vocabulary shared with the menu, Home and the island. The island itself has its own contract, [recording-island.md](recording-island.md). [AGENTS.md](../AGENTS.md) maps the other contracts; [`.omp/RULES.md`](../.omp/RULES.md) holds the invariants every change keeps.

## Console

- Native `Window("Voiceour", id: "main")`, one `TabView`: Home, Glossary, Journal, Settings. Home is a figures page of cards; Glossary and the Journal are three-pane browsers (sidebar, list, page) and Settings is a sidebar beside one page, all built from the [Kit](#kit). The window opens at 1164 × 820 pt and never narrows below 800 × 560 pt (`VoiceourMetrics.Window`): the root's `.frame(minWidth:minHeight:)` with `.windowResizability(.contentMinSize)`. Last tab reopens unless first-run guidance requires Home. The Journal tab's identifier stays `history`: `--console-section=history`, the `console.last-tab` default and `console.tab.history`.
- Glossary, Settings and Home MUST use native controls for input — `TabView`, `Toggle` (`.switch`), `Picker`, `TextField`, `SecureField`, `Stepper`, `Slider`, `ColorPicker`, context menus, confirmation dialogs — placed inside kit surfaces; buttons, search fields, folds, sidebars and state pills come only from the kit, which keeps the native behaviour this rule protects. NEVER custom control skins or window chrome. Every tab's content sits on `Kit.Screen`, painted in the resolved theme. Preserve system focus, metrics, VoiceOver, accessibility settings.
- Theme: Settings ▸ Appearance chooses an appearance, System, Light or Dark (`Settings.consoleAppearance`), and an accent colour (`Settings.consoleAccent`); nothing else is a user choice. `ThemeRoot`, applied once at the console root (`ConsoleWindowView`) and once at the menu root (`MenuView`), resolves them with the window's effective colour scheme (what System means), Increase Contrast and, for the System accent, `NSColor.controlAccentColor` (re-read on `NSColor.systemColorsDidChangeNotification`) into one `Theme` (`Theme.resolve`), and hands it down as `\.theme` together with the matching colour scheme and `.tint(theme.accent)`, so native controls agree with the painted surfaces. Increase Contrast raises contrast in every appearance on its own ([Visual vocabulary](#visual-vocabulary)). The window chrome follows the choice: an explicit Light or Dark becomes the app's AppKit appearance (`NSApplication.shared.appearance`, aqua or darkAqua) through `ThemeRoot.applyAppAppearance(_:)`, at launch in `VoiceourApp.init` before any window exists and whenever the choice changes, so the title bar, the tab strip and the menu popover follow it; System sets it to nil and macOS decides. The recording island draws no appearance-dependent pixels.
- Sliders: integer UI units with an explicit `step`; `.labelsHidden()` + `.accessibilityLabel`/`.accessibilityValue` (the spoken readout); trailing monospaced readout, hidden from AX. NEVER `minimumValueLabel`/`maximumValueLabel`: they publish tiny step buttons (`tiny-hit-target`). Radio `Picker`s keep one `AXRadioGroup` and lay their options out in a row (`.horizontalRadioGroupLayout()`).
- Destructive actions MUST use titled native confirmation dialogs with destructive roles.
- App styling inside the tabs: kit components and the Island showroom (production `MercurySurface`; [recording-island.md](recording-island.md)).
- Ground: `NSGlassEffectView(style: .regular)` behind the tab view (`ConsoleGlassGround`), the window chrome's one material; no app tint. Clear only `NSWindow.isOpaque` + `backgroundColor`. Reduce Transparency → `windowBackgroundColor`. NEVER place text directly on sampled desktop: every tab covers `ConsoleGlassGround` with `Kit.Screen`'s opaque `ground`. Console content uses no SwiftUI glass (`.glassEffect`, `GlassEffectContainer`, `.glassBackgroundEffect`, the `.glass` and `.glassProminent` button styles): every content surface, bar and sidebar is painted and opaque, so the offscreen harness captures what the reader sees.
- Settings is one page per section, chosen in a `Kit.Sidebar` of `Kit.SidebarItem`s (`settings.section.<raw>`, the `SettingsSection` raw value) in contract order: Dictation, Audio, Model, Backend (only with the debug panes, `LaunchOptions.showsDebugPanes`), Appearance, Island, Readiness, Capture, Privacy, Memory, Danger. No General tab. The tab opens on Dictation and NEVER persists the section; below `Kit.Metrics.railBelow` the sidebar folds to its rail, as the Journal's does. Readiness, Capture and Audio carry the worst attention among their readouts (`.critical` for a crit, `.caution` for a warn): Readiness the backend and microphone readouts, Capture the capture and insertion readouts, Audio the mute readout and a saved microphone that is missing. A page (`SettingsPage`, a `Kit.PageColumn` with no bar) opens with `SettingsSection.title` in the display face and `SettingsSection.sentence`, then `Kit.Group`s of `Kit.SettingRow`s separated by `Kit.Rule(inset: 12)`; a row's control is label-hidden and keeps its label as its accessibility label, and a destructive action sits last in a group of its own. A state word on a page is a sentence-case `Kit.Pill` (“Restart to apply”, “Mute on”, “Paste ready”). The Island page holds `ConsoleIslandSection` alone ([recording-island.md](recording-island.md)). Every copy a page offers goes through `SettingsClipboard.copy` and confirms in the tab's toast (`settings.copied`) only after `GeneralPasteboard.copy` succeeded: “Diagnostics copied to clipboard”, “Agent instructions copied to clipboard”, “Install command copied to clipboard”. Memory: the “Keep dictations in memory” toggle (`setMemoryEnabled`), Copy Agent Instructions (`MemoryPages.agentInstructions(root:)`), the Agent skill row's Copy Install Command, the “Sort entries with Jev” toggle and the TypeSafe key row. Danger: Clear History…, Clear Memory… (enabled while memory is on disk or holds entries), Clear Vocabulary…. Clear History's confirmation dialog carries a second destructive button, “Clear History and Memory”, offered on Clear Memory…'s terms, that erases memory too.
- Appearance (`settings.section.appearance`, symbol `circle.lefthalf.filled`, no attention), sentence “How the console and the menu look. The recording island keeps its own looks.”: an “Appearance” group holding `Kit.AppearancePicker` (System, Light and Dark tiles, `settings.appearance.system|light|dark`) with the footer “System follows macOS. Increase Contrast in System Settings › Accessibility raises contrast in every appearance.”; an “Accent colour” group holding `Kit.AccentPicker` (System, Green, Blue, Purple, Pink, Red, Orange, Yellow, Graphite; `settings.accent.<raw>`); a “Preview” group (`settings.appearance.preview`, one AX element labelled “Preview”, taking no clicks) drawing a selected row in a focused list, a primary and a secondary `Kit.Button`, the four status pills (“Ready”, “Will prompt”, “Denied”, “Downloading”) and an accent meter in the live theme. The pickers write through `settingBinding(coordinator, \.consoleAppearance)` and `\.consoleAccent`, which save at once; the console and the menu repaint in the choice. Defaults: System and Green. A stored value this build does not know reads as the default ([runtime.md › Persistence](runtime.md#persistence)).
- Privacy, after Data handling (Copy Diagnostics, `system.diagnostics.copy`): the “Link dictations to agent sessions” toggle (`system.agent-links.toggle`) calls `setAgentSessionBinding`, never a bare setting write. Below it, Earlier dictations: Link Earlier Dictations (`system.agent.link-earlier`) calls `linkEarlierDictations()` and is disabled while linking is off or a run is reading. Its caption reads “Finds earlier dictations whose exact words reached one omp or Claude Code session on this Mac, and links them to it.” before any run and after a run is cancelled, “Linking…” while a run reads, then the run's `LinkEarlierRun.summary` as it is, never rebuilt in the view ([runtime.md › Link Earlier Dictations](runtime.md#link-earlier-dictations)).
- Agent skill (Copy Install Command, `system.memory.copy-skill-command`) is enabled on Copy Agent Instructions' terms (memory on, or a folder on disk) and never while the app terminates. A press awaits `prepareAgentSkill()`, which writes the skill into the memory folder ([memory.md › Agent skill](memory.md#agent-skill)); only once the file is on disk does it copy `MemoryPages.skillInstallCommand(root:)` and confirm “Install command copied to clipboard” in the page's toast. The caption says to run it once in Terminal, that it links one skill into the omp, Claude Code and Codex skill folders that exist so every agent learns where the dictations are kept, that Voiceour writes only inside its own folder, that agents may ask before they read outside the project, and that a project with an omp includeSkills list must add voiceour-memory. A failed write copies nothing and sets the caption in the critical text: “The skill could not be written on this Mac.”; the next press restores it.
- “Sort entries with Jev” (`system.organizer.toggle`) calls `setOrganizerEnabled`, never a bare setting write, so turning it off cancels every labelling task. Its caption states what is sent, to whom, and that Jev returns labels only and writes no text. It is disabled while it is off and no key is set, and stays operable while on, so an “on” can always be turned off.
- The TypeSafe key row (`system.organizer.key`, a container element around the whole row) shows where the key comes from and NEVER the key (`system.organizer.key.status`: “From the TYPESAFE_API_KEY environment variable”, “Saved in typesafe.key” or “Not set”). A `SecureField` (`system.organizer.key.field`) and Save Key (`system.organizer.key.save`, disabled while the field is blank) call `saveTypeSafeKey`; the field empties when the save succeeds. Remove Key (`system.organizer.key.remove`, only while the key comes from the file) sits behind a titled destructive confirmation. A failed write sets the caption in the critical text: “The key file could not be changed on this Mac.”
- Home/Settings MUST share `ConsoleReadiness` values, sentences, remediation; both draw a readout's word as a sentence-case `Kit.Pill` (`Kit.Pill.sentence` of the stored label: “Model needed”, “Copy-only risk”) toned by `Kit.Pill.Tone(_:)` from its `ConsoleReadout.Severity`, with the remediation as a secondary `Kit.Button`. `DictationPolicy.owesFirstRunGuidance` = `Settings.hasCompletedFirstRun == false` AND both durable records empty; missing flag defaults false. `completeFirstRun()` stays outside the journaling branch: secure delivery and a saved note complete onboarding; refusal/cancel/failed decode does not.
- All showing routes MUST use `ConsolePresentation`: menu (Open Console and the Report's thread line), `--show-console`, `applicationShouldHandleReopen` (Dock, `open -a`, reopening), `onAppear`. Console open → `.regular`, front/deminiaturized; close → `.accessory`. `--no-activate` or `.prohibited` → no presentation management. Disable miniaturization and restoration.
- Thread route: `coordinator.pendingJournalThread` (an `AgentSessionKey`) asks the console to show one thread. When it is non-nil, on appear and on change, the window selects the Journal tab and the Journal tab selects that thread in Threads through `JournalNavigation.openThread`, then sets the request to nil. This holds whether the console was already open or opens because of the request; a key with no matching thread lands on Threads with its newest thread selected.

## Glossary

The Glossary tab shows the spellings dictation is held to, the spoken forms that reach them, and the corrections the last dictation suggested. What a term is, what an edit, an import or a suggestion may change, and what the editors offer belong to [text-pipeline.md › Glossary rules](text-pipeline.md#glossary-rules). Views: `ConsoleGlossaryTab.swift` (tab, `GlossaryShelf`) and `ConsoleTermEditor.swift`, the editor Timeline's teach (`ConsoleTeachHost`) also renders.

- The tab draws `Kit.Screen` and holds a `Kit.Sidebar` beside a `Kit.Split` (list column, page column); below `Kit.Metrics.railBelow` the sidebar folds to its rail, as the Journal's does. The sidebar lists All Terms (`glossary.origin.all`, every live term counted), then one item per origin that holds a live term (`GlossaryQuery.originFacets`), with its count: Yours (`glossary.origin.yours`) and Built-in (`glossary.origin.builtin`). An origin that holds no term is not listed, and a selected origin whose last term goes returns the sidebar to All Terms. While a suggestion is pending and not ignored, the heading “From your last dictation” (a `Kit.SidebarSection`, a rule on the rail) and Suggestions (`glossary.suggestions`, with its count) follow. On every appear the tab opens on Suggestions, the first one selected, while any are pending; otherwise it keeps its choice. Tombstoned terms are not live and never listed.
- List: “Glossary”, subtitled “N terms” (“1 term”), “M of N terms match” while a query or an origin narrows it, or “N suggestions” (“1 suggestion”) on Suggestions. Its bar holds the search field (`glossary.search.field`, “Search terms and spoken forms”, clear `glossary.search.clear`; Return selects the first match and focuses the list), then Add Term (`glossary.add-term`) and Import… (`glossary.import`, help “Import a newline- or JSON-array word list. Terms stay on this Mac, and duplicates are merged.”) as `Kit.IconButton`s that keep their titles as their accessibility labels. A failed import's reason shows as a caption in the critical text under the bar until the next import or search edit. A query typed on Suggestions switches to All Terms. A query that matches nothing shows a `Kit.EmptyState` in the list column, “Nothing matches “<query>”” (the query cut to 32 characters and “…”), with Clear Search (`glossary.search.nomatch.clear`); while an origin narrows the list its message reads “Search runs over <Yours|Built-in> terms and their spoken forms. All Terms in the sidebar searches every term.” The page keeps what it shows. ↑ and ↓ move the selection once the list holds focus; a row press focuses the list.
- Term rows are `Kit.TitleRow`s (`glossary.term.<termId>`, tooltip the canonical): the canonical spelling in the code face (`monospacedTitle`, `TextRole.code`) over “Heard as a · b” or “Matched by its spelling only”, and a neutral “Built-in” `Kit.Pill` on a bundled term. VoiceOver label: “<canonical>, heard as a, b” or “<canonical>, matched by its spelling only”. Context menu: Remove Term…. Suggestion rows (`glossary.suggestion.<id>`) read “<misheard> → <canonical>” in the code face over “Suggested correction”, VoiceOver label “Suggested correction: <misheard> becomes <canonical>”.
- Term page: the bar holds Remove Term… (`glossary.term.remove`, destructive, help “Remove this term from the glossary”) behind the titled destructive confirmation “Remove this term?” — “Dictation stops holding “<canonical>” to this spelling. Text you already pasted is not affected.” The header carries the origin as kicker, the canonical as title in the code face (`monospacedTitle`, `TextRole.codeTitle`) and the heard-as summary; then a card headed “Spelling and spoken forms” holds `ConsoleTermEditor` (prefix `glossary.term`, Save `glossary.term.save`, enabled only for a non-blank change), reseeded from the stored term after a save. Remove writes `settings.glossary` and calls `saveSettings()`. Nothing selected → a `Kit.EmptyState`, “No term selected”, described “Click a term to edit it. Case and spacing variants of a term are matched automatically.”
- Add Term opens the draft: a `Kit.DraftRow` “New term” (`glossary.draft.row`) at the head of the list, selected, and the “New term” page beside it, the same card with prefix `glossary.draft`, Save `glossary.draft.save` and Cancel `glossary.draft.cancel`. A spelling that is already a term is refused (““<canonical>” is already a term. Open it to add a spoken form.”). A saved draft selects the new term, on All Terms when Built-in was selected. Cancel removes the draft row and reopens the term that was open before the draft, if it is still a term. A draft that holds text survives leaving it: a row press, Return in the search field, ↑ or ↓, or opening Suggestions drops only a blank draft, and a draft with words stays as the unselected draft row until Save or Cancel. Add Term or a press on the draft row reopens it with its words; ↑ and ↓ treat the draft row as the list's first stop, and closing a term while a draft exists shows the draft page.
- Suggestion page: the bar holds Teach (`suggestion.<id>.accept`, primary, `acceptSuggestion`, label “Teach correction from <misheard> to <canonical>”), Ignore (`suggestion.<id>.ignore`, label “Ignore suggestion for <misheard>”; hides it while it stays pending and teaches nothing) and Never Suggest This (`suggestion.<id>.reject`, `rejectSuggestion`, help “Never offer this correction again. The pasted text is unchanged.”). The header reads “From your last dictation”, the canonical and “Heard as <misheard>”; a card headed “Suggested correction” shows the pair, as one element labelled like its row, and the caption “Accept teaches future dictation only — the text you already pasted is never changed.” An answer selects the next pending suggestion, else the previous; the last one answered returns the sidebar to All Terms, on the taught term after Teach and on nothing after Ignore or Never Suggest This. A refused Teach keeps the page.
- A successful import confirms in the page's toast (`glossary.imported`): “Imported 1 term” or “Imported N terms”.
- No live term, no draft and no suggestion → one `Kit.EmptyState` in place of the whole tab, sidebar included: “No terms yet” — “A term is the spelling Voiceour holds a word to when dictation keeps hearing it wrong. Add one, or import a word list.” — with Add Term (primary, `glossary.add-term`) and Import… (secondary, `glossary.import`) side by side, the one empty state with two actions, and the failure caption under them.
- Derived lists (matches, origin facets, the live count, the open term's forms and derived variants, visible suggestions) MUST be cached in state and rebuilt on appear and on change of the glossary, the pending suggestions, the query or the sidebar choice, NEVER in `body`.

## Journal

History is the record: the newest 500 dictations delivered to non-secure targets, stored in `recent-sessions.json`, cleared by Clear History. Memory is the durable, uncapped record in `<support>/memory/` ([memory.md](memory.md)), and the only one that holds notes and topics. The Journal tab shows both through five lenses, built from the [Kit](#kit). Views: `ConsoleJournalTab.swift` (tab, `JournalSidebar`), `JournalTimelineLens.swift` (with `ConsoleTeachHost.swift`), `JournalRewindLens.swift`, `JournalThreadsLens.swift`, `JournalTopicsLens.swift`, `JournalNotesLens.swift`, `JournalEntryRow.swift`, `JournalAgentNotes.swift`; pure grouping lives in `Sources/VoiceCore/Journal.swift` (`JournalQuery`).

- The tab draws `Kit.Screen` and holds `JournalSidebar`, a `Kit.Sidebar`, beside one lens. The sidebar lists one `Kit.SidebarItem` per lens (`journal.lens.<lens>`), in `JournalLens.allCases` order — Timeline, Rewind, Threads, Topics, Notes — with what it holds as a quiet count (History rows, threads, topics, notes; Rewind shows none), then “Recent threads” (a `Kit.SidebarSection`): the five threads with the newest entries (`journal.sidebar.thread`), each a `Kit.SidebarItem` with the `terminal` glyph, labelled “<title>, <agent>” (“…, not sent” while one of its dictations was not sent), and, while one was not sent, the loud caution attention badge in place of a count (AX value “needs attention”, tooltip “<title>. A dictation in this session was not sent”); a press calls `JournalNavigation.openThread`. While the tab is narrower than `Kit.Metrics.railBelow` (1,000 pt), as a window the user narrowed stays across launches, the sidebar folds to a rail of glyphs (`Kit.Metrics.railWidth`), Recent threads under a rule, each item keeping its name and facts as its label, value and tooltip and its attention as a corner dot. The tab opens on Timeline unless a thread route is pending ([Console](#console)); NEVER persist the lens. `RenderOverrides.journalInitialLens`, `journalInitialDay` and `journalInitialThread` pin a lens state for the harness.
- Every lens is a `Kit.Split`: a list column (`Kit.ListColumn`, titled with the lens's name and subtitled with its count) beside a page column (`Kit.PageColumn`) that shows the selected item. A row press selects its item and gives the list focus; a press on the selected row keeps it; ↑ and ↓ move the selection once the list holds focus and scroll the row into view. The selected row shows the active selection while its list holds focus and the inactive one otherwise ([Kit](#kit)). With nothing selected and a non-empty list, a lens selects its first row (Timeline keeps its own rule, below). When the selected item disappears, the item that took its place in the list is selected, else the one before it, else nothing. A search that hides the selection leaves its page on screen and shows a no-results `Kit.EmptyState` in the list column, echoing the query, with Clear Search. Nothing selected → a `Kit.EmptyState` on the page with no action. A lens with nothing at all shows one first-use `Kit.EmptyState` in place of both columns.
- Every group of content on a page — its folds, the teach editor, Highlights, a block, the agent notes, Dictations, Entries, Details, a creation or edit form, a note's text — sits in a `Kit.Card`, headed by its `Kit.SectionHeader` inside when the group has a heading (`JournalSectionCard`). The transcript sits in its own `sunken` well. The page header and Rewind's figures sit on the page's ground.
- Timeline reads History's rows. Rewind, Threads, Topics and Notes read `coordinator.journalEntries`: every memory entry plus each History row memory does not hold, oldest first, memory winning for an id both hold. A lens NEVER stores anything of its own: topic edits and filing go through the coordinator into memory, and the only network request a lens can lead to is Sort Entries ([memory.md › Sorting](memory.md#sorting)).
- Derived lists (entries, days, blocks, threads, topic pages, matches) MUST be rebuilt on appear, on change of History's row ids or bindings, and on change of `coordinator.memoryRevision` (Topics also on `coordinator.memoryTopics`), NEVER in `body`.
- Rewind, Threads, Topics and Notes MUST take the calendar from `RenderOverrides.calendar ?? .current` and render month and weekday names from fixed arrays, so goldens never depend on the locale.
- A copy a page offers confirms in the lens's toast (`Kit.Flash`; `sessions.detail.copied`, `journal.rewind.copied`, `journal.threads.copied`, `journal.topics.copied`, `journal.notes.copied`), in the sentence VoiceOver hears, and only after `GeneralPasteboard.copy` succeeded. A reading row confirms its own copy ([Reading rows](#reading-rows)).

### Timeline

- List: “Timeline”, subtitled “N dictations” (“1 dictation”), or “M of N dictations match” while a query or a filter narrows it. Its bar holds the search field (`sessions.search.field`, “Search dictations”, clear `sessions.search.clear`; Return selects the first match and focuses the list) and, only while some row has a delivery target, the app filter (`sessions.filter`, a glyph-only `Kit.MenuButton` titled “Filter by app”, help “Show dictations from one app”, holding an inline `Picker`: All Apps, then “<label> (<count>)”); under them, one `Kit.FilterChip` per filter in force: the app (clear `sessions.app-filter.clear`, “Show all apps”) and the agent session, named by `displayTitle` (clear `sessions.agent-filter.clear`, “Show all agent sessions”).
- Search, app filter and agent-session filter are ANDed; the agent-session filter keys on `agentSession?.key`. Facets: count descending, display label, bundle id; app name from newest row. Last matching app row disappears → drop filter; same for the agent-session filter's last bound row. The menu re-sorts resolved labels; `RecentSessionQuery.appFacets` preserves its pure order.
- Rows, grouped by day under `Kit.GroupHeader`s with the day's count, are `Kit.PreviewRow`s: stamp, muted glyph, destination icon (`Kit.AppIcon`) and name, the outcome pill (“Pasted” success, “Copy only” caution or “Failed” critical; `RecentSessionOutcomeMetadata.outcomeMark`), a “Not sent” caution pill when the bound session never sent the dictation (`AgentSessionBinding.isNotSent`), then a two-line preview. The name is the app's, except on a row bound to an agent session, which names its thread instead: `AgentSessionBinding.displayTitle` (“<Agent> · <title>”, else “<Agent> · <folder name>”, else “<Agent> session”), beside the app's icon, because every bound row went to the same terminal. The row's VoiceOver label says the same: stamp, outcome, “Not sent” when it shows, “to <destination>”, word count, muted when it was, then the preview.
- Selection: the first visit selects the newest row unless `RenderOverrides.historyStartsDeselected`; after that only the reader moves it, and a reload never reselects what the reader left. Nothing selected → “No dictation selected”, “Select a dictation to read it, copy it or teach a word from it.”
- Page bar: Copy (`sessions.detail.copy`, primary), Fix / Teach (`sessions.detail.teach`, ⌘T), Open Thread (`sessions.detail.thread`, bound rows) and More (`sessions.detail.more`): Show Only *App*, Show Only This Agent Session, Copy Resume Command (only when `AgentSessionBinding.resumable`), Unlink from Thread, Delete Transcript…. Header: the day and time as kicker, then the thread's `displayTitle`, else the app's label, else “Dictation”, then the word count (after “Pasted into <app>” on a bound row), then the outcome pill, a non-normal safety pill (“Terminal”, “Code editor”, “Secure”, “Unknown”; `TargetSafetyClass.displayLabel`), “Not sent” and the muted glyph.
- The transcript well (`sunken`, 1 pt `border`, radius 10, 16 pt padding) holds `SelectableTranscriptText` at 15 pt in the theme's `text1`, its selection in the theme's `selection` (`sessions.detail.transcript`, label “Transcript”, value “<n words>, recorded <detail stamp>”, named actions “Copy transcript” and “Teach a correction”). Its height is measured on a scratch layout at the width SwiftUI proposes, and the live text view keeps its text container at the width it is placed at, so the drawn lines always fill exactly the height reserved for them; measuring NEVER resizes the live view. A theme change recolours the words in place and keeps the reader's selection. A single click copies all delivered text as a plain, non-transient string (“Transcript copied to clipboard”). Selection or right-click `Fix / Teach “word”`, then ⌘T or Fix / Teach, teaches. One caption under the well names the selected teaching surface or the instruction; the teach editor (`ConsoleTeachHost`) opens in a card under it.
- Sent (only when the bound session's sent prompt differs from the delivered text: `AgentSessionBinding.sentText != nil`, `sessions.detail.sent`), Raw (only when different, `sessions.detail.raw`) and Details (`sessions.detail.details`) MUST be sibling `Kit.Disclosure`s in one card, independent, all closed on each newly selected row. Details, as `Kit.Property` rows: Target (friendly app + non-normal safety pill), Agent (`displayTitle`, `sessions.detail.agent`, + monospaced `locationLine`, with ` · Not sent` appended when `isNotSent`; no send wording while pending; for evidence `words`, a secondary line `Linked by its words`, `sessions.detail.evidence`; on an unbound row with `unlinked`, one plain secondary line `Not linked. <sentence>` instead, `sessions.detail.unlinked`, sentences in [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)), Timings, least-sure word. No evidence → omit Details; a miss is evidence.
- Row context menu: Copy Transcript, Fix / Teach a Word, Show Only *App*, then — on an agent-bound row — Open Thread, Show Only This Agent Session, only when resumable Copy Resume Command (`AgentSessionBinding.resumeCommand`, shell-quoted), and Unlink from Thread (`unlinkThread(rowID:)`: no confirmation; the row keeps its text and shows `Not linked. You removed this link.`, and nothing links it again), Delete Transcript…, behind the titled destructive confirmation “Delete this transcript?”.
- Words: a row is a dictation, never a session. No row → `Kit.EmptyState` “No dictations yet”, “Completed dictations are kept here with their transcripts, timestamps and word counts.” followed by `ConsoleHotkeyHint.fullGesture`, no action. A query that matches nothing → “Nothing matches “<query>””, with Clear Search (`sessions.search.nomatch.clear`); filters alone that match nothing → “Nothing matches these filters”, “No dictation went to this app in this agent session.”, with Clear Filters (`sessions.filter.nomatch.clear`), which lifts both; each chip's clear button lifts its own filter. A failed delete reads “Could not delete this dictation — it is still on disk. Try again.”
- Timeline reloads derived rows when any row's `agentSession` changes, and calls `refreshAgentSessions()` on appear, when the set of row ids changes, and on selection ([runtime.md › Agent session binding](runtime.md#agent-session-binding)). It keeps every `sessions.*` identifier.

### Rewind

- List: “Rewind”, subtitled “N days”. Every day that holds an entry, newest first, grouped by month (“June 2025”) as `Kit.TitleRow`s (`journal.rewind.day-row`): “Sunday, Jun 15” over “3 entries · 37 words · 2 apps”. The selected day is seeded from `RenderOverrides.journalInitialDay`, else the newest day; a day that loses its entries passes the selection to the next older day, else the next newer. No day at all → `Kit.EmptyState` “Nothing to rewind yet”, “Dictate something, then come back to replay your day.”; nothing selected → “No day selected”.
- Search field `journal.rewind.search` (“Search everything you said”, clear `journal.rewind.search.clear`) turns the list into matches from every day: text, session title, project folder, app name; newest first under day headers, at most 200 shown, the count in the subtitle (“4 matches”, “1 match”, “Showing the newest 200 of N matches”). A match press selects its day and marks that entry on the page, scrolled into view; the page keeps showing the selected day while the search runs. A search shows entries only, never an agent note. A query that matches nothing → “Nothing matches “<query>””, with Clear Search (`journal.rewind.no-matches.clear`).
- Page bar: Earlier Day (`journal.rewind.earlier`) and Later Day (`journal.rewind.later`), glyph-only `Kit.IconButton`s that step only through days that hold entries and are disabled at the ends, then Copy Recap Prompt (`journal.rewind.recap-prompt`, primary), only when the selected day holds at least one entry memory keeps.
- The page names the day, then its figures as `Kit.MetricTile`s two to a row: Entries (count and words; `journal.rewind.entries`, AX value “<count> · <n> words”), Speaking time (only when measured), Where (agent sessions, apps, notes), Span (first to last time). With the recap prompt, a caption: “Paste it into your coding agent. The agent reads this day in the memory folder and saves a recap there.”
- Highlights: when the day has a confident label, a “Highlights” section lists the day's decision, idea, to-do and question entries in time order (`RewindDay.highlights`, kind confidence ≥ `JournalQuery.highlightConfidence`). Then, when agents saved notes for the day, “From your agents” ([Agent notes](#agent-notes)).
- Then one section per block, in time order. A block is a run of consecutive entries on one subject: the same agent session, the same app when no session is bound, or notes with no session (“Notes”); a pause longer than 30 minutes starts a new block. A subject that returns later in the day is marked “continued”. A session block carries Open Thread beside its heading, and its session title has a context menu: Open Thread and, only when resumable, Copy Resume Command.

### Threads

- Agent sessions grouped by working directory: the folder's name is the heading; sessions with no known directory sit under “No project folder”, last. List: “Threads”, subtitled “N agent sessions”, or “N of M agent sessions match” while searching. A thread row (`journal.threads.row`, a `Kit.TitleRow` led by a small `terminal.fill` `Kit.IconTile`) shows title, then agent, dictation count and time span, and a “<n> not sent” caution pill; its VoiceOver label adds the not-sent count to the same facts, and its named action is “Open thread”. The title is the session's own title, else its project folder's name, else “<Agent> session”, never an id prefix; the row, the sidebar and the page read the same one (`JournalThreadsLens.title(of:)`). Memory's thread pages keep `JournalThread.displayTitle`, whose bare-thread fallback ends with the id's first 8 characters, because an agent finds its own page by its id.
- Selection is the tab's `openThread`, so another lens, the sidebar or the menu's thread route can select a thread; when it names no listed thread, the newest one is selected. Nothing selected → “No thread selected”.
- Page bar: Copy Resume Command (`journal.threads.resume`, primary, resumable sessions only), Show in Timeline (`journal.threads.timeline`, only while one of the thread's entries is in History; sets Timeline's agent-session filter), Copy Outcome Prompt (`journal.threads.outcome-prompt`, only when memory keeps one of the thread's entries, so its thread page exists).
- The page names the agent and folder, the title, and “<n> dictations · <span>” with “<k> not sent” when any were not. Then “From the session” ([Agent notes](#agent-notes)), or, when no agent note names the thread and the outcome prompt is offered, a card saying no outcome is recorded yet and that Copy Outcome Prompt asks the session's agent for it; then “Dictations”, every one oldest first under day captions; then a card holding the Details `Kit.Disclosure` (`journal.threads.details`) with Session id (`journal.threads.session`) and Folder (`journal.threads.folder`, when known) as `Kit.Property` rows, closed whenever another thread is selected.
- Search field `journal.threads.search` (clear `journal.threads.search.clear`) filters threads by the same fields as Rewind; nothing matching shows “Nothing matches “<query>”” in the list column, whose Clear Search is `journal.threads.nomatch.clear`.
- No thread → `Kit.EmptyState` “No agent sessions yet” across both columns, whose message reads the setting. Linking off: “Turn on Link dictations to agent sessions in Settings ▸ Privacy. A dictation that you paste into Tern then joins its session here.” Linking on: “Paste a dictation into an omp or Claude Code pane in Tern.”

### Topics

- Topics are the user's ([memory.md › Topics](memory.md#topics)). List: “Topics”, subtitled “N topics”; its bar holds New Topic (`journal.topics.new`, a secondary `Kit.Button`, help “Name a new topic”).
- New Topic opens a draft, as Notes opens a new note: a `Kit.DraftRow` “New topic” (`journal.topics.draft`) at the head of the list, selected, and a draft page in the page column: the title “New topic”, then a card with Name (`journal.topics.new.name`, focused) and Summary, “What belongs here, in one line” (`journal.topics.new.summary`), Return in either adding the topic, then a trailing row of Cancel (`journal.topics.new.cancel`, secondary, Escape, help “Discard this topic”) and Add Topic (`journal.topics.add`, primary, disabled while the name is blank). A refusal shows as a caption in the critical text under the fields (`journal.topics.new.refusal`) in words that say what to change, and clears when the name changes. New Topic with a draft already open returns to it with its words. A press on a topic row leaves the draft row in place, unselected, its words kept; ↑ and ↓ walk the draft row first, then the topics. The draft lives in the tab (`JournalTopicDraft`), so its words survive a trip to another lens. Add Topic closes the draft and selects and reveals the new topic; Cancel discards it and returns to the topic selected when it opened, else the first topic. Nothing is ever a form in the list column.
- Rows: every topic, most entries first, then by name compared case- and diacritic-insensitively without the locale, then by id. A row (`journal.topics.row`, a `Kit.TitleRow` led by a small `tag.fill` `Kit.IconTile`) shows the name and “<n> entries · <summary>” (summary omitted when empty); its VoiceOver label reads “<name>, <n> entries, <summary>” and its named action is “Open topic”. A topic with nothing filed still has a row.
- Page bar: Copy Synthesis Prompt (`journal.topics.synthesis-prompt`, primary) and Delete Topic… (`journal.topics.delete`, destructive) behind the titled destructive confirmation “Delete this topic?” — “Its entries stay in memory and become unfiled.”
- The page names the topic (kicker “Topic”) and its summary, then “From your agents” when agents saved notes whose `topic` is this topic's id ([Agent notes](#agent-notes)), then “Entries”, newest first under day captions, as `JournalEntryRow`s, then “Name and summary”: Name (`journal.topics.name`) and Summary (`journal.topics.summary`) fields and Save (`journal.topics.save`, enabled only when the trimmed fields differ from the topic; a refusal shows in `journal.topics.refusal`), then, only while `settings.organizerEnabled` and a key is set, “Sorting”: Sort Entries (`journal.topics.sort`, `sortEntries()`), replaced by Stop Sorting (`journal.topics.sort.stop`, `cancelSortEntries()`) while a run is in flight, and a caption (`journal.topics.sort.status`) from `organizerRun`: what the run does before any run, “Sorting <done> of <total>…” during one, “Sorted <n> entries.” after one, plus “<failed> could not be sorted.” when any failed. Nothing selected → “No topic selected”.
- No topic and no draft: one `Kit.EmptyState` across both columns, “No topics yet” — “Name a topic, then file dictations and notes under it from their menu.” — with New Topic (primary, `journal.topics.new`). Cancelling the draft with no topic returns to it.

### Notes

- Every `.note` entry, newest first (equal times by id), grouped under `SessionsFormatters.dayHeader` headers. Day groups are cached in state and rebuilt on appear and on change of the entries or the query, NEVER in `body`. List: “Notes”, subtitled “N notes”, or “N of M notes match” while searching.
- The list's bar holds “Take a Note” (`journal.notes.take`, primary) that calls `startNote()`; while the note it started records (`.recording` with `captureIntent == .note`) it reads “Finish Note” and calls `stopAndProcess()`. It is disabled while any other dictation is recording or processing. While the list holds rows, a caption under it names the spoken command and says a note is pasted nowhere.
- With at least one note: search field `journal.notes.search` (clear `journal.notes.search.clear`) over every note's text and agent session (`JournalQuery.matches`), on every day at once. A query that matches nothing shows “No note matches “<query>”” in the list column, whose Clear Search button is `journal.notes.no-matches.clear`. With no note at all: one `Kit.EmptyState` across both columns, “No notes yet” — “Take a note from here or from the menu, or say “note to self” at the start of a dictation.” — whose action is Take a Note (`journal.notes.take`; “Finish Note” while the note records, disabled while another dictation is busy). Nothing selected → “No note selected”.
- Rows are `Kit.PreviewRow`s with “Not sent” and kind pills, whose VoiceOver label reads “<time>, note, [not sent, ][<kind>, ]<text>”, with a context menu: Copy Text, Open Thread (note has a session), File Under, Delete Entry….
- Page bar: Copy (`journal.notes.copy`, primary, “Note copied to clipboard”), File Under (`journal.entry.file`, a `Kit.MenuButton`), Open Thread (`journal.notes.thread`, note has a session) and Delete… (`journal.notes.delete`) behind the titled destructive confirmation “Delete this entry?”; a failed delete reads “The entry could not be deleted.” (`journal.entry.delete-error`). The page names the day and time, “Note”, and the session's title or “Saved to memory. Nothing was pasted or copied.”, with the note's pills, then its whole text in a card, selectable.

### Agent notes

- Agent notes are the Markdown files agents saved under memory's `agents/`; what counts as one, and the limits, belong to [memory.md › Agent access](memory.md#agent-access). `ConsoleJournalTab` calls `refreshAgentNotes()` when the tab appears, when the lens changes and when a thread is selected, including when another thread replaces the selected one, and passes `coordinator.agentNotes` and `coordinator.memoryStore.root` to Rewind, Threads and Topics. NEVER load them in `body`; the coordinator loads them off the main actor.
- Per note, one `JournalAgentNoteRow` (`journal.rewind.agent-note` in Rewind, `journal.threads.agent-note` on a thread's page, `journal.topics.agent-note` on a topic's page): a plain row inside its section's card, ruled off from the next note by a `Kit.Rule`, drawing no surface of its own: a small `sparkles` `Kit.IconTile`, a caption reading “<title> · by <author> · YYYY-MM-DD HH:mm”, the title being the file name when the note has none and the time the file's modification time in the lens calendar, then the body in the reading face. Rewind's “From your agents” shows the notes whose `day` is the selected day; a topic's “From your agents” shows the notes whose `topic` is its id; a thread's “From the session” shows the notes whose `session` equals the thread's file stem (`MemoryPages.threadFileStem`), newest modification first, and the Threads lens picks them again whenever the selected thread or the loaded notes change. No matching note → no section.
- The body is plain, selectable text: NEVER rendered as Markdown, a link or an attributed string, NEVER executed or opened. At most 4,000 characters show; a longer body is cut there and ends with “…”. An agent note is not a `JournalEntryRow` and is never one of the user's entries: no copy on click, no context menu, no File Under or Delete Entry…, no search match, no day figure or count.
- Copy Recap Prompt, Copy Synthesis Prompt and Copy Outcome Prompt (`JournalPromptCopyButton`) copy `MemoryPages.recapPrompt(day:root:calendar:)`, `MemoryPages.synthesisPrompt(topic:root:)` and `MemoryPages.outcomePrompt(thread:day:root:calendar:)` with `GeneralPasteboard.copy` and confirm in the page's toast: “Recap prompt copied to clipboard”, “Synthesis prompt copied to clipboard” or “Outcome prompt copied to clipboard”; a refused clipboard write shows and says nothing. Recap requires an entry memory keeps on that day (`memoryIDs`, the ids in `coordinator.memoryEntries`), because the day page the prompt names exists only then. Copy Outcome Prompt names the day of the thread's latest entry in the planner calendar (`DictationCoordinator.memoryCalendar`, in the lens calendar's zone). Voiceour calls no writing model: the prompt goes to the user's own agent, which saves its note under `agents/`.

### Reading rows

- Rewind, Threads and Topics pages render entries as `JournalEntryRow`: the time in `meta` with monospaced digits in a 60 pt gutter (`Kit.Metrics.stampGutter`) + the whole text in `reading` (15 pt with 2 pt of extra leading), NEVER truncated, pills closing the first line. A row stands on a 20 pt rhythm from 44 pt: its content, centred, in the smallest of 44, 64, 84, 104… pt that holds it, so every row height is on the row scale or the 4 pt grid whatever the face's line height. The row is the control: a click copies the text as a plain, non-transient string; a transient “Copied” success pill in the gutter and the VoiceOver announcement “Text copied to clipboard” confirm it. A Rewind search match's row is lit as selected (`Kit.RowButtonStyle`).
- Pills, in sentence case: “Note” (info) on a note; “Not sent” (caution) when the bound session never sent the dictation; a neutral kind pill (“Idea”, “Decision”, “To-do” or “Question”, `UtteranceKind.displayName`) when the entry's label names that kind with confidence ≥ `JournalQuery.highlightConfidence`, the bar Rewind's Highlights use (`JournalEntryRow.highlightKind(of:)`). All are words, and VoiceOver reads them before the text.
- Context menu: Copy Text; Show in Timeline (row still in History); Open Thread (row has a session); File Under; Delete Entry… only when History does not hold the entry (every note), behind a titled confirmation dialog with a destructive role, deleting the memory entry with that id. Teach, Raw, Sent and Details stay in Timeline, and so does Delete for a row History holds; NEVER add them to a reading row.
- File Under (`JournalFileUnderItems`, and `JournalFileUnderChoices` inside a page's File Under menu): one item per topic in memory's order, the entry's effective topic checked, then No Topic; choosing calls `fileEntry(id:underTopic:)`. With no topics it holds one disabled item, “No topics yet”.

### App identity

- `AppIdentity`: installed Finder display name > persisted name > `AppDisplayName.label(bundleId:name:)`; bundle id stays key, never display label. Icon: `Kit.AppIcon` (the app's icon, else a monogram if uninstalled), 32 pt on Home's top-app rows and 16 pt beside the destination name on Timeline rows; Target and the app filter chip have names only.
- `InstalledAppCatalog`: sole bundle-id LaunchServices lookup, main-actor/process-lifetime cached. `RenderOverrides.installedApps` pins goldens. The live menu's *Will paste into <app>* and *Will copy for <app>* (no class name) and the Report's outcome detail use `AppDisplayName` directly.

## Kit

The component kit is `Sources/Voiceour/Kit*.swift` (`KitTokens`, `KitSurfaces`, `KitLayout`, `KitControls`, `KitRows`, `KitPickers`, `KitContent`, `KitHome`), every component under the `Kit` namespace. Every console tab is built from it; `console.kit.gallery` and `a11y.kit.reduce-transparency` render every component, `Kit.Hero` included, in a console composition — sidebar, list, page, cards ([ui-harness.md › Scenes](ui-harness.md#scenes)).

- One layer, painted. Every component reads `@Environment(\.theme)` and paints only theme roles ([Visual vocabulary](#visual-vocabulary)), so one set of components serves both appearances, every accent and Increase Contrast without a branch of its own. Every fill under text is opaque. Kit text goes through `.roleStyle(_:)` (`TextRole`), whose default colour comes from the theme, and every painted surface under text declares `\.surfaceGround`, so the contrast lint measures what the reader sees. `Text.roleStyle(_:).foregroundStyle(_:)` renders the colour it records: `RoleStyledText` applies the colour once, because `Text` keeps the first foreground it is given; a non-`Text` label takes `.roleStyle(_:color:)`.
- No SwiftUI glass (`.glassEffect`, `GlassEffectContainer`, `.glassBackgroundEffect`, the `.glass` and `.glassProminent` button styles) in content, bars or sidebars: glass takes its look from whatever lies under it, and the offscreen harness cannot capture it. The window chrome's `ConsoleGlassGround` is the console's one material ([Console](#console)); every other view composes kit components.
- Reduce Transparency (system or harness pin, through `A11y`) drops the light theme's card shadow, the one see-through layer, and the card's outline steps up from `separator` to `border` in its place; every fill is already opaque. Increase Contrast resolves the higher-contrast theme (`Theme.isIncreasedContrast`): separators and borders step up a rung, cards and key caps take the `borderStrong` outline, pills and the sidebar's attention badge add a 1 px border in their text colour, and the card shadow and top highlight drop. Differentiate Without Color adds a pill's glyph for every stateful tone and turns the heat ladder into size steps; Reduce Motion drops every kit animation (`Kit.Motion`).
- Measures (`Kit.Metrics`), on the 4 pt grid. Columns are flush (`gutter` 0), each drawing its trailing 1 pt rule inside its own width: the sidebar 222 pt (`sidebarWidth`) and its rail 54 pt (`railWidth`), the list column 320 pt (`listWidth`), each including its hairline; the page column takes the rest, its content in a centred 680 pt reading measure (`readableWidth`) inside 24 pt padding (`pagePadding`), sections 24 pt apart (`sectionGap`). Inside the tab view's 3 pt insets, at the 1164 pt default a Settings page is 936 pt and a Journal or Glossary page 616 pt; at the 800 pt minimum, the sidebar on its rail, a Journal page is 420 pt. The off-grid lint checks these widths. Controls: 28 pt, radius 6 (`controlHeight`, `controlRadius`), a glyph in a 16 pt box so a tall symbol cannot push the control off the scale; the clear button in a search field or a filter chip is a 24 × 24 pt target (`glyphTarget`). Rows: one-line 32 pt (`rowHeightOne`), two-line 48 pt (`Kit.TitleRow`, `rowHeightTwo`), preview 64 pt (`rowHeightPreview`), each a least height so a CJK or emoji line grows its row rather than clipping; radius 6, inset 4 pt from the column's edge (`rowRadius`, `rowInset`); sidebar items 28 pt; reading rows 44, 64, 84 and 104 pt for one to four lines. The lint's control scale (`allowedControlHeights` in `UILint`) is 24 / 28 for controls and 32 / 40 / 44 / 48 / 64 for rows. Cards: radius 12, padding 16 (`cardRadius`, `cardPadding`). Pills: 18 / 22 pt (`pillHeightSmall`, `pillHeightRegular`). Icon tiles: 28 / 20 / 16 pt (`iconTileRegular`, `iconTileSmall`, `iconTileMini`). Toast: at least 36 pt tall, at most 440 pt wide (`toastHeight`, `toastMaxWidth`). Property labels: 120 pt (`propertyLabelWidth`); a reading row's time: 60 pt (`stampGutter`).
- Selection is VS Code's, in every list (`Kit.RowButtonStyle`): a selected row in the list that holds keyboard focus (`\.kitListFocused`, which `Kit.ListColumn` publishes) takes the accent-tinted `selection` plate and a 2 pt `focusRing` bar 4 pt from its leading edge, the row's height less 12 pt; a selected row in a list without focus takes the neutral `selectionInactive` plate, so the reader always sees which column the arrow keys move. Hover and press are `hover` / `pressed` washes; at rest a row draws nothing, and rows draw no separators. A selected row carries the `.isSelected` trait. A sidebar's selected item takes the quiet `selectionInactive` plate, so chrome never competes with the list.
- Layout: `Kit.Screen` (the theme's `ground` under the safe area, the content inside it; declares the ground). `Kit.Sidebar` (a solid `sunken` column, flush, closed by a 1 pt separator; it sizes itself, `sidebarWidth` or `railWidth` under `kitCompactControls`, so callers never frame it; 8 pt padding, items 2 pt apart, scrolling when a short window cannot hold them). `Kit.SidebarSection` (a quiet `label` heading in `text3` over the items it groups; on the rail a rule whose tooltip and accessibility header label are its name). `Kit.Split` (the list column, its separator, the page column; the list keeps its width and the page takes the rest). `Kit.ListColumn` (the title in `heading`, the subtitle in `meta`, a bar, then a lazy stack of rows with pinned `Kit.GroupHeader`s, which paint the `ground` across the rows' inset; a separator appears under the header only once rows scroll beneath it; with a `focus` binding the arrow keys move the selection (`onMove`), and `reveal` scrolls a row into view). `Kit.PageColumn` (a solid 48 pt bar of trailing page actions in `ground`, whose separator appears once content scrolls under it; the actions fall back to their glyphs alone and then to a sideways-scrolling bar, so none clips; then the reading measure; `identity` restarts the scroll per item and `reveal` centres one element). `Kit.PageHeader` (a kicker in `text3`; the title in `title`, at most two lines, or in `codeTitle` with middle truncation under `monospacedTitle`; a meta line, at most two lines, so a term with forty heard-as forms keeps its header short and lists them whole in its editor; then wrapping accessory pills). `Kit.SectionHeader` (a `heading` with an optional trailing control or figure). `Kit.EmptyState` (centred, at most 320 pt wide: a 36 pt glyph in `text3`, a `heading` title, a `body` message in `text2`, at most one primary `Kit.Button`; the empty Glossary alone adds a secondary one. Three uses, never a generic placeholder: first use, no results (the title echoes the query, the action clears it) and all clear (no action); a place with nothing at all shows one across both its columns, never a cramped form in the list column).
- Surfaces: `Kit.Card` (the `raised` fill, radius 12, a 1 pt outline drawn over its content so a row's hover plate never covers it — `separator` beside the light theme's soft shadow, `border` wherever no shadow draws (dark, or Reduce Transparency), `borderStrong` under Increase Contrast — and the light theme's shadow or the dark theme's 1 pt top highlight; it clips its content to its corners). `Kit.Group` (a System Settings group: an optional `label` header, a `Kit.Card` with no padding holding the rows, an optional `meta` footer; callers place `Kit.Rule(inset: 12)` between rows). `Kit.Rule` (a 1 pt `separator`, horizontal or vertical, `inset` at both ends).
- Controls: `Kit.Button` (the one labelled action control, 28 pt: `.primary` the accent fill with `onAccent`, at most one per bar; `.secondary` the `raised` plate in a `borderStrong` outline; `.plain` an `accentText` word; `.destructive` `critical.text` on `raised` in a `border` outline, with the destructive role; hover and press step the fill; a 2 pt `focusRing` ring outside the plate for the keyboard. A disabled button draws its title in `textDisabled`, and a disabled primary draws the `hover` plate, never the accent fill, so it never looks actionable). `Kit.IconButton` (a 28 pt glyph-only action, no plate until the pointer is over it, its label its tooltip and accessibility label). `Kit.MenuButton` (a native `Menu` drawn without a bezel; a titled one adds a chevron; requires an identifier: a bare-symbol menu otherwise publishes the symbol's name). `Kit.SearchField` (a 28 pt `sunken` well in a `border` that becomes a 2 pt `focusRing` while focused; Escape clears, Return runs `onSubmit`, its clear button labelled “Clear search”). `Kit.FilterChip` (a 24 pt `hover` capsule in a `border`: a leading glyph and the title, so the state never rests on colour, then a clear button). `Kit.Disclosure` (the whole 28 pt heading row is the button, its AX value “Expanded” or “Collapsed”, its chevron turning with the fold). `Kit.FocusRingStyle` (a plateless button style that draws only the keyboard's ring, for a fold heading or a picker tile). Every text-field prompt is drawn in `text3`, so it never reads as a value. Under the `kitCompactControls` environment value a button, a menu button and a sidebar item draw their glyph alone and keep their title as their accessibility label; `Kit.PageColumn` sets it on its bar when the titles do not fit the page's width, and every tab with a sidebar sets it on the sidebar's rail.
- `Kit.SidebarItem`: a 28 pt row with a glyph (`accentText` when selected, `text2` otherwise), a name (`rowTitle` in `text1` when selected, `body` in `text2` otherwise), then either a quiet count (`label` digits in `text3`, grouped in a pinned `en_US` locale) or a loud `attention` badge (`.caution` a triangle, `.critical` an octagon, in a 16 pt capsule of the status wash, carrying the count when there is one), never both; on the rail the glyph alone with a 6 pt corner dot for attention and a tooltip of its name and facts. One accessibility element that combines its children and keeps the press, labelled by the name, valued by the count then “needs attention” (“3, needs attention”, or “needs attention” with no count), with `.isSelected` when selected. `Kit.SettingRow`: one preference in a `Kit.Group`, at least 36 pt with 12 pt insets: the title in `body` over its caption in `meta` (in `captionColor` when the words already say a state), the control trailing on the title's line; the text column keeps at least half the row, so a wider control moves under the caption instead of squeezing the title. The caption is a sibling of the control, never its label.
- Rows: `Kit.PreviewRow` (a `meta` line in `text3` — time, app, its pills trailing — over two `body` lines of the words; the facts truncate down to a 96 pt floor before the pills give way), `Kit.TitleRow` (an optional leading icon tile, the name in `rowTitle`, or in `code` under `monospacedTitle`, over one `meta` line in `text2`, trailing pills or a figure), `Kit.LineRow` (a leading glyph or icon, a `rowTitle` name, a trailing `meta` fact), `Kit.DraftRow` (the unsaved item at the head of a list while its draft page is open — “New topic”, “New term” — a `square.and.pencil` glyph and the name in italic `body` in `text2`). Every row is one accessibility element whose children combine, keeps the press and the label its caller gives it, and carries `.isSelected` when selected.
- Content: `Kit.Hero` (Home's greeting in `hero`, a heading), `Kit.StatTile` (card content: the label in `meta` with an optional mini icon tile, the value in `figure` scaling to 60 % before it would truncate, the unit in `body`; one AX element labelled by the label and valued by “value unit”), `Kit.Figure` (`figureSmall` over a `meta` label; one AX element), `Kit.MetricTile` (its own small card: label, `figureSmall` value, `meta` detail; AX label the label, AX value “value · detail”), `Kit.MeterRow` (a leading app icon, the name in `body` over an accent `Kit.Meter`, the figure over its caption; one AX element labelled by the title, valued by `accessibilityValue`), `Kit.Meter` (a 4 pt capsule on `meterTrack`, filled in `accent` for a share and silent to VoiceOver, or in the info hue for a model download, a static-text element labelled “Model download” and valued “N%”, which callers never re-wrap; a non-zero fraction keeps at least a dot, NaN reads as 0), `Kit.IconTile` (an SF Symbol in `accentText` on an `accentWash` rounded square, 28 / 20 / 16 pt; hidden from VoiceOver), `Kit.AppIcon` (the app's icon while this Mac has it, else the first grapheme of its name on an `accentWash` square, `app.dashed` for a blank name; hidden from VoiceOver), `Kit.AppLabel` (a 14 pt `Kit.AppIcon` beside the name, in the line's own type), `Kit.Property` (a 120 pt `meta` label column beside the value in `body`; one AX container named by the label), `Kit.Fact` (a `Kit.Property`), `Kit.KeyCap` (`micro` on the `hover` plate in a 1 px `border`; a static-text element labelled by its key, so a caller's label and value, such as the menu's “Capture hotkey” and “Fn or Globe”, reach VoiceOver).
- Pickers: `Kit.AppearancePicker` draws System, Light and Dark as 88 × 60 pt miniatures of the console (a sidebar, a selected row with its focus bar, a card with an accent button), each painted from `Theme.resolve` for its own scheme with the reader's accent and contrast, System split Light and Dark; the chosen tile carries a 2 pt `focusRing` ring and an accent check, each its name under it. `Kit.AccentPicker` draws nine 22 pt swatches in 28 pt targets, each the accent the theme actually paints for this appearance and contrast, System a sweep of four hues; the chosen one is ringed and its name sits under the row. Both are buttons labelled by the name, with `.isSelected` and their `settings.appearance.*` and `settings.accent.*` identifiers.
- `Kit.Pill` is the one state word everywhere — the console, Settings, Home's checklist, the menu: a fully rounded capsule, 18 pt (`.small`) or 22 pt (`.regular`), the word in `label` in the tone's text colour on its wash, shown exactly as given: callers pass sentence case, and `Kit.Pill.sentence(_:)` converts a stored uppercase word (“COPY-ONLY RISK” → “Copy-only risk”). Tones: `.neutral` (`text2` on `hover`), `.accent` (`accentText` on `accentWash`), `.success`, `.caution`, `.critical` and `.info` (each status's text on its wash); `Kit.Pill.Tone(_:)` maps a `ConsoleReadout.Severity`. A caller's glyph shows; `.critical` always shows `xmark.octagon.fill`, and Differentiate Without Color adds every stateful tone's glyph. A long word truncates at its tail rather than pushing its row's other text out. Inside a disabled group it keeps its word and loses its hue. To accessibility it is plain text, so inside a combined row it joins the row's label and never becomes its value; never selectable.
- Confirmation: `Kit.Flash` holds one message at a time for 2 s (`Kit.Flash.hold`) and announces it to VoiceOver; `.kitToast(_:identifier:)` shows it as `Kit.Toast` centred 16 pt above the bottom edge — a success glyph and the message in `body` on the `overlay` surface, wrapping to a second line and then truncating in the middle — and publishes the space it covers (`\.kitToastInset`), so the scrolling columns beneath extend past it. A caller shows a message only after the write it reports succeeded.

## Visual vocabulary

`Theme.swift` and `ThemeGenerator.swift` own every colour the console and the menu paint; `DesignTokens.swift` owns type (`VoiceourTypography`, `TextRole`), spacing (`VoiceourMetrics.Space`) and the window measures. Native controls take the theme's accent through `.tint` and its colour scheme. The recording island keeps its own palette ([recording-island.md](recording-island.md)); the Island page's stage and the look gallery's wells paint the constant studio colour `IslandStudio.ground` in every appearance.

- Generator: `ThemeGenerator.palette(scheme:accent:increasedContrast:systemAccent:)` is pure, deterministic OKLCH math. From a fixed base per appearance — dark `oklch(0.150 0.014 258)` with contrast level k = 0.45, light `oklch(0.985 0.006 250)` with k = 0.50 — it steps the surfaces (dark elevates with lighter fills and sinks the sidebar; light lifts cards to white and greys the sidebar), composites every wash over `raised` and stores it opaque, then solves each text role, line and accent role against the opaque colours it is painted on. `Theme.resolve(scheme:accent:increasedContrast:systemAccent:)` is the only constructor views use, memoised per input; `Theme.fallback` (dark, Green, standard contrast) is what anything outside a `ThemeRoot` sees.
- Accents, requested in OKLCH: Green 0.86 0.19 147 · Blue 0.62 0.19 258 · Purple 0.62 0.20 300 · Pink 0.68 0.20 350 · Red 0.63 0.21 25 · Orange 0.74 0.17 55 · Yellow 0.87 0.17 95 · Graphite 0.70 0.012 258 · System `NSColor.controlAccentColor` in sRGB, Blue when AppKit cannot express it there. The generator moves only lightness, to the value nearest the request where `onAccent` (white tried before ink) and the fill both pass; in Light a yellow-family hue that must drop below L 0.55 turns 12° toward orange.
- Status hues: success 152°, caution 78°, critical 27°, info 228°, each pushed at least 35° from the accent's hue, toward the side it already sits on unless that lands within 35° of another status (Green → success 182°); a near-colourless accent (chroma < 0.04, Graphite) pushes none. Selected never reads as succeeded.
- Contrast targets, standard → Increase Contrast: `text1` lerp(11, 15, k) → 15.1; `text2` lerp(5.6, 7.5, k); `text3` 4.6 → 5.6; `textDisabled` lerp(2.3, 3, k); `accentText` and status text 4.6 → 7, also on their washes; `onAccent` 4.5 → 7 on the fill and both its states; the fill ≥ 3:1 on every container; `focusRing` 3.2 → 4.5; `separator` lerp(1.25, 1.6, k) → 3.05; `border` lerp(1.7, 3, k) → 3.05; `borderStrong` 3.05 → 4.55; `meterTrack` lerp(1.5, 2, k) → 3.05. Text roles are measured on `ground`, `sunken`, `raised`, `overlay`, `hover`, `pressed` and `selection`. Increase Contrast adds 0.30 to k, moves each line up a rung and drops the card shadow and top highlight. `Tests/VoiceourTests/ThemeTests.swift` asserts every ratio for every accent × appearance × contrast.
- Heat ladder: `heat[0]` is the `hover` wash, a day with no dictation; steps 1–4 are quartiles of the busiest day, climbing from `raised` toward the accent in OKLCH lightness and chroma at the accent's hue and ending at `accent`. Differentiate Without Color keeps the empty step and draws busier days as size steps in `accent`.
- The accent is the one action colour: primary buttons, switches, selection, focus rings, icon tiles, share meters, the heat ladder; text takes it only as `accentText`. Status hues say state, never decorate.

- SF throughout; monospaced faces only for code-like content and the greeting; figures take monospaced digits so a changing count never jitters. Every surface declares `surfaceGround` for the contrast lint.
- `MenuBarExtra(.window)`: 280 pt, three whitespace-separated blocks: Status (state, optional mute, Fn, headline), Report (failure/transcript/outcome; absent when empty), Actions (primary + grouped commands). `ThemeRoot` themes it at `MenuView`'s root, and the popover paints an opaque theme `ground` (`MenuGround`), so no system material shows through. The status pill is a regular `Kit.Pill` in sentence case (“Idle”, “Live”, “Working”, “Preparing”, “Error”, an outcome such as “Pasted”, or a failure title through `Kit.Pill.sentence`, such as “Mic blocked”), in the info tone while a session is live or in flight; the mute pill a small neutral “System audio muted”; the hotkey a `Kit.KeyCap` “Fn”. The headline is `meta` in `text2`, or in the caution or critical text. Each command row is 32 pt and leads with a mini `Kit.IconTile`, its title in `body`, then a `text3` chevron or a `Kit.KeyCap`, on the `raised` command container with `hover` and `pressed` washes and a focus ring; command rows keep their titles. The primary action is a full-width 32 pt accent capsule (`PrimaryActionButtonStyle`: `Kit.Button(.primary)`'s fill, `onAccent` title and state ladder) titled “Start Dictation”, “Stop Dictation” or “Open Console”, its AX labels “START DICTATION”, “STOP DICTATION” and “OPEN CONSOLE”. The transcript well is `sunken` in a `border`, `hover` under the pointer, and holds only the transcript; a click copies it, and “Copied to the clipboard.” in the success text under the well confirms the write until the transcript changes. Download/warmup MUST stay visible; re-poll health while acquisition advances.
- Menu outcome: the Report's pill and detail are `InsertionOutcome.summary(in: coordinator.lastDeliveredApp)`; `CaptureModels.swift` holds the exact sentences. “Pasted” → “Pasted into <app>.” (“Pasted.” when the app is unknown); “Copy only” → why, in one plain sentence that names the app when it is known, then “Press ⌘V to paste.” (a cancel after the copy: “Cancelled. The text is on the clipboard.”); “Delivery failed” → one plain sentence per reason. Every reason `InsertionSafetyPolicy` and `PasteboardInserter` can produce has its own sentence; only an unknown string falls back to the humanized reason. The state name stays `pasteAttempted`, and the island's announcements keep their own words. `lastDeliveredRowID` (nil for a secure target or a note) and `lastDeliveredApp` are set with `lastOutcome` and cleared with it.
- Menu link line: inside Report, never a command row, only when the reported outcome is `.pasteAttempted`, `settings.agentSessionBindingEnabled` is on, and the History row `lastDeliveredRowID` names exists. A bound row shows one borderless button (`menu.report.thread`, at least 28 pt tall): `displayTitle` in `accentText` on one tail-truncated line and a trailing `chevron.right` in `text3`, AX label “Open thread, <displayTitle>”; it sets `pendingJournalThread` and opens the console as Open Console does ([Console](#console)). A row with `unlinked` shows the caption `Not linked. <sentence>` (`menu.report.unlinked`; [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)). Neither → nothing while the link resolves. The line arrives with the menu's report transition, respecting Reduce Motion, and the Actions container keeps its three rows.
- Menu notes: the Actions block's grouped commands carry “Take a Note” (`menu.take-note`, calls `startNote()`) only while no dictation or note is in flight, the menu is not gated (`errorMessage == nil`), and no failure remedy row (Try Again, Open System Settings) shows; the remedy row takes its place so the container keeps three rows. While a note records (`captureIntent == .note`) the Status headline's target line reads “Will save as a note”. A saved note reports as `InsertionOutcomeSummary.noteSaved` from `lastSavedNoteID`, under the gate a delivery outcome uses (no error, nothing in flight): pill “Note saved”, Report detail “Saved to memory. Nothing was pasted or copied.”; `.noteSaved` itself falls to “Idle” with the delivery states.
- Motion: quick 0.14 s, standard 0.18 s, deliberate 0.22 s. MUST respect Reduce Motion. Animate menu report/state resizing; native console keeps system behavior; resting settings stay static except the Island showroom (live only while visible, still under Reduce Motion).
- Controls MUST have stable human labels. NEVER encode state only in colour. Pills carry words; Differentiate Without Color adds symbols. Captions stay separate from control AX labels. Gesture-only behavior requires named AX actions; completion announces.
- `micro` sets only key caps and chart axes. NEVER micro subtext: labels, hints or counts beside content; a fact the reader needs takes the `meta` voice.

# Native UI contract

The console window, the Journal tab, and the visual vocabulary shared with the menu, Home and the island. The island itself has its own contract, [recording-island.md](recording-island.md). [AGENTS.md](../AGENTS.md) maps the other contracts; [`.omp/RULES.md`](../.omp/RULES.md) holds the invariants every change keeps.

## Console

- Native `Window("Voiceour", id: "main")`, one `TabView`: Home, Glossary, Journal, Settings. Glossary, Settings and each Journal lens are grouped `Form`s; Home is a figures page. Last tab reopens unless first-run guidance requires Home. The Journal tab's identifier stays `history`: `--console-section=history`, the `console.last-tab` default and `console.tab.history`.
- MUST use native controls: `TabView`, grouped `Form`, `Section`, `Toggle`, `Picker`, `TextField`, `LabeledContent`, `Button`, `Slider`, `ColorPicker`, `DisclosureGroup`, search, context menus. NEVER custom chrome, control skins, forced dark window appearance. Preserve system accent, focus, metrics, VoiceOver, accessibility settings.
- Sliders: integer UI units with an explicit `step`; `.labelsHidden()` + `.accessibilityLabel`/`.accessibilityValue` (the spoken readout); trailing monospaced readout, hidden from AX. NEVER `minimumValueLabel`/`maximumValueLabel`: they publish tiny step buttons (`tiny-hit-target`). Radio `Picker`s stay direct Form rows; an `HStack` wrapper splits one into a group per item.
- Destructive actions MUST use titled native confirmation dialogs with destructive roles.
- App styling inside Forms: monospaced code values, `ConsoleStateMark`, `ConsoleCaption`, `ConsoleRow`, `MeterBar`, the Island showroom (production `MercurySurface`). Native-plate meters/marks use system semantic colours; `StatusChip` uses app palette.
- Ground: `NSGlassEffectView(style: .regular)` behind native section plates; no app tint. Clear only `NSWindow.isOpaque` + `backgroundColor`. Reduce Transparency → `windowBackgroundColor`. NEVER place text directly on sampled desktop or use SwiftUI `.glassEffect` in shipping views.
- Settings order: Dictation, Audio, Model, debug-only Backend, Island, Readiness, Capture, Privacy, Memory, Danger. No General tab. Memory: the “Keep dictations in memory” toggle (`setMemoryEnabled`), Copy Agent Instructions (`MemoryPages.agentInstructions(root:)`), the “Sort entries with Jev” toggle and the TypeSafe key row. Danger: Clear History…, Clear Memory… (offered while `memoryExistsOnDisk`), Clear Vocabulary…. Clear History's confirmation dialog carries a second destructive button, “Clear History and Memory”, that erases memory too.
- “Sort entries with Jev” (`system.organizer.toggle`) calls `setOrganizerEnabled`, never a bare setting write, so turning it off cancels every labelling task. Its caption states what is sent, to whom, and that Jev returns labels only and writes no text. It is disabled while it is off and no key is set, and stays operable while on, so an “on” can always be turned off.
- The TypeSafe key row (`system.organizer.key`, a container element) shows where the key comes from and NEVER the key (`system.organizer.key.status`: “From the TYPESAFE_API_KEY environment variable”, “Saved in typesafe.key” or “Not set”). A `SecureField` (`system.organizer.key.field`) and Save Key (`system.organizer.key.save`, disabled while the field is blank) call `saveTypeSafeKey`; the field empties when the save succeeds. Remove Key (`system.organizer.key.remove`, only while the key comes from the file) sits behind a titled destructive confirmation. A failed write turns the caption red: “The key file could not be changed on this Mac.”
- Home/Settings MUST share `ConsoleReadiness` values, sentences, remediation. `DictationPolicy.owesFirstRunGuidance` = `Settings.hasCompletedFirstRun == false` AND both durable records empty; missing flag defaults false. `completeFirstRun()` stays outside the journaling branch: secure delivery and a saved note complete onboarding; refusal/cancel/failed decode does not.
- All showing routes MUST use `ConsolePresentation`: menu (Open Console and the Report's thread line), `--show-console`, `applicationShouldHandleReopen` (Dock, `open -a`, reopening), `onAppear`. Console open → `.regular`, front/deminiaturized; close → `.accessory`. `--no-activate` or `.prohibited` → no presentation management. Disable miniaturization and restoration.
- Thread route: `coordinator.pendingJournalThread` (an `AgentSessionKey`) asks the console to show one thread. When it is non-nil, on appear and on change, the window selects the Journal tab and the Journal tab opens Threads on that thread through `JournalNavigation.openThread`, then sets the request to nil. This holds whether the console was already open or opens because of the request; a key with no matching thread opens Threads with none open.

## Journal

History is the record: the newest 500 dictations delivered to non-secure targets, stored in `recent-sessions.json`, cleared by Clear History. Memory is the durable, uncapped record in `<support>/memory/` ([memory.md](memory.md)), and the only one that holds notes and topics. The Journal tab shows both through five lenses. Views: `ConsoleJournalTab.swift` (tab, lens picker), `ConsoleHistoryTab.swift` (Timeline), `JournalRewindLens.swift`, `JournalThreadsLens.swift`, `JournalTopicsLens.swift`, `JournalNotesLens.swift`, `JournalEntryRow.swift`; pure grouping lives in `Sources/VoiceCore/Journal.swift` (`JournalQuery`).

- Every lens MUST be its own grouped `Form` whose first section is the lens picker: a native segmented `Picker` (`journal.lens`) with Timeline, Rewind, Threads, Topics, Notes, in that order (`JournalLens.allCases`). The tab opens on Timeline unless a thread route is pending ([Console](#console)); NEVER persist the lens. `RenderOverrides.journalInitialLens`, `journalInitialDay` and `journalInitialThread` pin a lens state for the harness.
- Timeline reads History's rows. Rewind, Threads, Topics and Notes read `coordinator.journalEntries`: every memory entry plus each History row memory does not hold, oldest first, memory winning for an id both hold. A lens NEVER stores anything of its own: topic edits and filing go through the coordinator into memory, and the only network request a lens can lead to is Sort Entries ([memory.md › Sorting](memory.md#sorting)).
- Derived lists (entries, days, blocks, threads, topic pages, matches) MUST be rebuilt on appear, on change of History's row ids or bindings, and on change of `coordinator.memoryRevision` (Topics also on `coordinator.memoryTopics`), NEVER in `body`.
- Rewind, Threads, Topics and Notes MUST take the calendar from `RenderOverrides.calendar ?? .current` and render month names from fixed arrays, so goldens never depend on the locale.

### Timeline

- Exactly one open transcript; its own grouped `Section` directly below selected row, inside that day. Each day names itself once and renders one–three plates.
- Closed rows: stamp, outcome mark (PASTED, COPY ONLY or FAILED), word count, destination icon/name, two-line preview. While one opens, others fade to 0.45 (0.8 under Increase Contrast). Open heading omits preview.
- The open transcript is the control; no detail action buttons. Single click copies all delivered text as a plain, non-transient string; transient COPIED TO CLIPBOARD mark + VoiceOver confirmation. Selection/right-click `Fix / Teach “word”` + ⌘T teaches. One footer: selected teaching surface, instruction, or copy confirmation.
- `HistoryInputMonitor`: margin click/Escape close; ⌘T teaches. Transcript MUST expose named copy/teach accessibility actions.
- Row context menu: Copy Transcript, Fix / Teach a Word, Show Only *App*, then — on an agent-bound row — Open Thread, Show Only This Agent Session and, only when `AgentSessionBinding.resumable`, Copy Resume Command (`AgentSessionBinding.resumeCommand`, shell-quoted), Delete.
- Raw (only when different), Sent (only when the bound session's sent prompt differs from the delivered text: `AgentSessionBinding.sentText != nil`) and Details MUST be sibling `DisclosureGroup`s, independent bindings, all closed on each newly opened transcript. Details: Target (friendly app + non-normal safety chip), Agent (`displayTitle` + monospaced `locationLine`, with ` · Not sent` appended when `isNotSent`; no send wording while pending; on an unbound row with `unlinked`, one plain secondary line `Not linked. <sentence>` instead, `sessions.detail.unlinked`, sentences in [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)), Timings, least-sure word. No evidence → omit Details; a miss is evidence. Labels MUST carry ids + explicit default AX actions; the SwiftUI triangle reports successful press without toggling.
- Search + app filter + agent-session filter are ANDed; the agent-session filter keys on `agentSession?.key`. `Menu`-wrapped inline `Picker` exists only with delivery-target rows. Facets: count descending, display label, bundle id; app name from newest row. One `N of M sessions match` caption. Last matching app row disappears → drop filter; same for the agent-session filter's last bound row. Menu re-sorts resolved labels; `RecentSessionQuery.appFacets` preserves its pure order.
- Timeline reloads derived rows when any row's `agentSession` changes, and calls `refreshAgentSessions()` on appear, when the set of row ids changes, and on selection ([runtime.md › Agent session binding](runtime.md#agent-session-binding)).
- Timeline keeps every `sessions.*` identifier.

### Rewind

- Replays one day. Navigator row: Earlier Day (`journal.rewind.earlier`), a day menu (`journal.rewind.day`), Later Day (`journal.rewind.later`); they step only through days that hold entries. The menu lists the 14 newest days, then one submenu per earlier month.
- Day figures: Entries (count and words; `journal.rewind.entries`), Speaking time (only when measured), Where (agent sessions, apps, notes), Span (first to last time).
- Then one `Section` per block, in time order. A block is a run of consecutive entries on one subject: the same agent session, the same app when no session is bound, or notes with no session (“Notes”); a pause longer than 30 minutes starts a new block. A subject that returns later in the day is marked “continued”. A session block shows the session title with a context menu: Open Thread and, only when resumable, Copy Resume Command.
- Search field `journal.rewind.search` (“Search everything you said”, clear `journal.rewind.search.clear`) replaces the day with matches from every day: text, session title, project folder, app name; newest first, at most 200 shown, one caption that states the count.
- Highlights: when the day has a confident label, a “Highlights” section between the navigator and the blocks lists the day's decision, idea, to-do and question entries in time order (`RewindDay.highlights`, kind confidence ≥ `JournalQuery.highlightConfidence`).
- Copy Recap Prompt (`journal.rewind.recap-prompt`) in the navigator section, only when the selected day holds at least one entry memory keeps, with a caption: “Paste it into your coding agent. The agent reads this day in the memory folder and saves a recap there.” Then, when agents saved notes for the day, a “From your agents” section before the blocks ([Agent notes](#agent-notes)). A search shows entries only, never an agent note.

### Threads

- Agent sessions as pages, grouped by working directory: the folder's name is the heading; sessions with no known directory sit under “No project folder”, last. A thread row shows title, agent, dictation count, time span and not-sent count.
- Exactly one open thread; its page is its own `Section` directly below its row: Session id (`journal.threads.session`), Folder, Copy Resume Command (`journal.threads.resume`, resumable sessions only), Show in Timeline (`journal.threads.timeline`, sets Timeline's agent-session filter), then every dictation oldest first under day captions. A thread page MAY carry these two bordered buttons; the no-detail-buttons rule binds only Timeline's open transcript.
- Search field `journal.threads.search` (clear `journal.threads.search.clear`) filters threads by the same fields as Rewind.
- No bound dictation → the lens says how to turn on Settings ▸ Privacy ▸ Link dictations to agent sessions.

### Topics

- Topics are the user's ([memory.md › Topics](memory.md#topics)). First section after the picker, “New topic”: Name (`journal.topics.new.name`), “What belongs here, in one line” (`journal.topics.new.summary`) and Add Topic (`journal.topics.add`, disabled while the name is blank). A refusal shows as a red caption under the button (`journal.topics.new.refusal`) in words that say what to change.
- “Sorting” section, only while `settings.organizerEnabled` and a key is set: Sort Entries (`journal.topics.sort`, `sortEntries()`), replaced by Stop Sorting (`journal.topics.sort.stop`, `cancelSortEntries()`) while a run is in flight, and a caption (`journal.topics.sort.status`) from `organizerRun`: what the run does before any run, “Sorting <done> of <total>…” during one, “Sorted <n> entries.” after one, plus “<failed> could not be sorted.” when any failed.
- “Topics”: every topic, most entries first, then by name compared case- and diacritic-insensitively without the locale, then by id. A row (`journal.topics.row`) is a plain button with the name and “<n> entries · <summary>” (summary omitted when empty) that opens or closes its page; the open state is carried by a chevron and the selected trait, and a named action opens or closes it. A topic with nothing filed still has a row.
- Exactly one open topic; its page is its own `Section` directly below its row, as in Threads: Name (`journal.topics.name`) and Summary (`journal.topics.summary`) fields, Save (`journal.topics.save`, enabled only when the trimmed fields differ from the topic; a refusal shows in `journal.topics.refusal`), and Delete Topic… (`journal.topics.delete`) behind the titled destructive confirmation “Delete this topic?” — “Its entries stay in memory and become unfiled.” Then the topic's entries, newest first under day captions, as `JournalEntryRow`s.
- The open topic's page also carries Copy Synthesis Prompt (`journal.topics.synthesis-prompt`) and, when agents saved notes whose `topic` is this topic's id, a “From your agents” block ([Agent notes](#agent-notes)).
- No topics: an unavailable view below “New topic” that says to name a topic and file entries from their menu.

### Notes

- Every `.note` entry, newest first (equal times by id), grouped under `SessionsFormatters.dayHeader` captions. Day groups are cached in state and rebuilt on appear and on change of the entries or the query, NEVER in `body`.
- First section after the picker: a “Take a Note” button (`journal.notes.take`) that calls `startNote()`; while the note it started records (`.recording` with `captureIntent == .note`) it reads “Finish Note” and calls `stopAndProcess()`. It is disabled while any other session or processing is in flight. A caption under it names the spoken command and says a note is pasted nowhere.
- With at least one note: search field `journal.notes.search` (clear `journal.notes.search.clear`) over every note's text and agent session (`JournalQuery.matches`), on every day at once. A query that matches nothing shows one unavailable view whose Clear Search button is `journal.notes.no-matches.clear`. With no note at all: an unavailable view that names the menu, this lens and the spoken command.
- Rows are `JournalEntryRow`s with `isInHistory` false, so each offers Delete Entry… and never Show in Timeline.

### Agent notes

- Agent notes are the Markdown files agents saved under memory's `agents/`; what counts as one, and the limits, belong to [memory.md › Agent access](memory.md#agent-access). `ConsoleJournalTab` calls `refreshAgentNotes()` when the tab appears and when the lens changes, and passes `coordinator.agentNotes` and `coordinator.memoryStore.root` to Rewind and Topics. NEVER load them in `body`; the coordinator loads them off the main actor.
- A “From your agents” block lists, per note, one `JournalAgentNoteRow` (`journal.rewind.agent-note` in Rewind, `journal.topics.agent-note` on a topic's page): a `ConsoleCaption` with the title, or the file name when the note has none, and “by <author>”, then the body. Rewind shows the notes whose `day` is the selected day; an open topic's page shows the notes whose `topic` is its id. No matching note → no block, so with no agent notes both lenses render as they do without them.
- The body is plain, selectable text: NEVER rendered as Markdown, a link or an attributed string, NEVER executed or opened. At most 4,000 characters show; a longer body is cut there and ends with “…”. An agent note is not a `JournalEntryRow` and is never one of the user's entries: no copy on click, no context menu, no File Under or Delete Entry…, no search match, no day figure or count.
- Copy Recap Prompt and Copy Synthesis Prompt copy `MemoryPages.recapPrompt(day:root:calendar:)` and `MemoryPages.synthesisPrompt(topic:root:)` with `GeneralPasteboard.copy`, show a transient COPIED mark (`ConsoleStateMark("COPIED", .ok)`) and announce “Recap prompt copied to clipboard” or “Synthesis prompt copied to clipboard” to VoiceOver. Recap requires an entry memory keeps on that day (`memoryIDs`, the ids in `coordinator.memoryEntries`), because the day page the prompt names exists only then. Voiceour calls no writing model: the prompt goes to the user's own agent, which saves its note under `agents/`.

### Reading rows

- Rewind, Threads, Topics and Notes render entries as `JournalEntryRow`: timestamp + the whole text, NEVER truncated. The row is the control: a click copies the text as a plain, non-transient string; transient COPIED mark + VoiceOver confirmation.
- NOTE mark on a note; NOT SENT mark when the bound session never sent the dictation; a kind mark (IDEA, DECISION, TO-DO or QUESTION) when the entry's label names that kind with confidence ≥ `JournalQuery.highlightConfidence`, the bar Rewind's Highlights use. All are words, and VoiceOver reads them before the text.
- Context menu: Copy Text; Show in Timeline (row still in History); Open Thread (row has a session); File Under; Delete Entry… only when History does not hold the entry (every note), behind a titled confirmation dialog with a destructive role, deleting the memory entry with that id. Teach, Raw, Sent and Details stay in Timeline, and so does Delete for a row History holds; NEVER add them to a reading row.
- File Under: one item per topic in memory's order, the entry's effective topic checked, then No Topic; choosing calls `fileEntry(id:underTopic:)`. With no topics it holds one disabled item, “No topics yet”.

### App identity

- `AppIdentity`: installed Finder display name > persisted name > `AppDisplayName.label(bundleId:name:)`; bundle id stays key, never display label. Icon: Home badge (monogram if uninstalled), Timeline `Control.inlineIcon`; Target/filter chip have names only.
- `InstalledAppCatalog`: sole bundle-id LaunchServices lookup, main-actor/process-lifetime cached. `RenderOverrides.installedApps` pins goldens. The live menu's *Will paste into <app>* and *Will copy for <app>* (no class name) and the Report's outcome detail use `AppDisplayName` directly.

## Visual vocabulary

`DesignTokens.swift` owns values. App palette belongs to menu, island, Home only.

| token / role | contract |
| --- | --- |
| `Ink.void` | opaque sRGB (0.02, 0.03, 0.05) |
| `Text.high`, `Text.mid`, `Text.low` | (0.89, 0.91, 0.95); (0.64, 0.71, 0.80); (0.51, 0.56, 0.64) |
| cyan / mint / amber / crimson | active-live-focus / success / degraded-waiting / failure-destructive |
| `micro`, `caption`, `label` | 10 / 12 / 13 pt |
| `tileValue`, `metric`, `heroMetric` | 20 / 32 / 64 pt |
| `hair`, `xs`, `sm`, `md`, `lg`, `xl` | 2 / 4 / 8 / 12 / 16 / 24 pt |
| controls | 24 / 28 / 32 / 40 pt; compact status marks: 20 pt |

- One dominant signal colour/view. `Alien.bloom`/heat ladder: Home fill/glyph/glow only, NEVER text. Four steps = quartiles of busiest day; Differentiate Without Color substitutes size steps at one hue.
- `OnGlass` cyan/mint/amber/crimson: system-glass text only, ≥4.5:1 against white and black; not painted/opaque grounds.
- Home islands remain fixed-dark in either appearance. Paint `Ink.pane` + `glassTint` + specular/`Alien` rims; NEVER stack another material over the glass ground. Declare `surfaceGround` for contrast lint.
- `MenuBarExtra(.window)`: 280 pt, three whitespace-separated blocks: Status (state, optional mute, Fn, headline), Report (failure/transcript/outcome; absent when empty), Actions (primary + grouped commands). The transcript well holds only the transcript; a click copies it, and a mint caption under the well confirms the write until the transcript changes. Download/warmup MUST stay visible; re-poll health while acquisition advances.
- Menu outcome: the Report's chip and detail are `InsertionOutcome.summary(in: coordinator.lastDeliveredApp)`; `CaptureModels.swift` holds the exact sentences. PASTED → “Pasted into <app>.” (“Pasted.” when the app is unknown); COPY ONLY → why, in one plain sentence that names the app when it is known, then “Press ⌘V to paste.” (a cancel after the copy: “Cancelled. The text is on the clipboard.”); DELIVERY FAILED → one plain sentence per reason. Every reason `InsertionSafetyPolicy` and `PasteboardInserter` can produce has its own sentence; only an unknown string falls back to the humanized reason. The state name stays `pasteAttempted`, and the island's announcements keep their own words. `lastDeliveredRowID` (nil for a secure target or a note) and `lastDeliveredApp` are set with `lastOutcome` and cleared with it.
- Menu link line: inside Report, never a command row, only when the reported outcome is `.pasteAttempted`, `settings.agentSessionBindingEnabled` is on, and the History row `lastDeliveredRowID` names exists. A bound row shows one borderless button (`menu.report.thread`): `displayTitle` on one tail-truncated line and a trailing secondary `chevron.right`, AX label “Open thread, <displayTitle>”; it sets `pendingJournalThread` and opens the console as Open Console does ([Console](#console)). A row with `unlinked` shows the caption `Not linked. <sentence>` (`menu.report.unlinked`; [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)). Neither → nothing while the link resolves. The line arrives with the menu's report transition, respecting Reduce Motion, and the Actions container keeps its three rows.
- Menu notes: the Actions block's grouped commands carry “Take a Note” (`menu.take-note`, calls `startNote()`) only while no session is active, the menu is not gated (`errorMessage == nil`), and no failure remedy row (Try Again, Open System Settings) shows; the remedy row takes its place so the container keeps three rows. While a `.note` session is active the Status headline's target line reads “Will save as a note”. A saved note reports as `InsertionOutcomeSummary.noteSaved` from `lastSavedNoteID`, under the gate a delivery outcome uses (no error, no active session): chip “NOTE SAVED”, Report detail “Saved to memory. Nothing was pasted or copied.”; `.noteSaved` itself falls to IDLE with the delivery states.
- Motion: quick 0.14 s, standard 0.18 s, deliberate 0.22 s. MUST respect Reduce Motion. Animate menu report/state resizing; native console keeps system behavior; resting settings stay static except the Island showroom (live only while visible, still under Reduce Motion).
- Controls MUST have stable human labels. NEVER encode state only in colour. Chips/marks carry words; Differentiate Without Color adds symbols. Captions stay separate from control AX labels. Gesture-only behavior requires named AX actions; completion announces.
- `micro` sets only chips, keycaps, the primary capsule and chart axes. NEVER micro subtext: labels, hints or counts beside content; a fact the reader needs takes the caption voice.

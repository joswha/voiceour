# Native UI contract

The console window and its tabs, the component kit they are built from, and the visual vocabulary shared with the menu, Home and the island. The island itself has its own contract, [recording-island.md](recording-island.md). [AGENTS.md](../AGENTS.md) maps the other contracts; [`.omp/RULES.md`](../.omp/RULES.md) holds the invariants every change keeps.

## Console

- Native `Window("Voiceour", id: "main")`, one `TabView`: Home, Glossary, Journal, Settings. Home is a figures page of islands; Glossary and the Journal are three-pane browsers (sidebar, list, page) and Settings is a sidebar beside one page, all built from the [Kit](#kit). Last tab reopens unless first-run guidance requires Home. The Journal tab's identifier stays `history`: `--console-section=history`, the `console.last-tab` default and `console.tab.history`.
- Glossary, Settings and Home MUST use native controls for input — `TabView`, `Toggle` (`.switch`), `Picker`, `TextField`, `SecureField`, `Stepper`, `Slider`, `ColorPicker`, context menus, confirmation dialogs — placed inside kit surfaces; buttons, search fields, folds, sidebars and state marks come only from the kit, which keeps the native behaviour this rule protects. NEVER custom control skins or window chrome. Every tab's content sits on `Kit.Screen`, which fixes the content's colour scheme to dark so it reads the same in either system appearance, as Home's islands always have; the window's own appearance is NEVER forced: the title bar and the tab strip follow the system. Preserve system accent, focus, metrics, VoiceOver, accessibility settings.
- Sliders: integer UI units with an explicit `step`; `.labelsHidden()` + `.accessibilityLabel`/`.accessibilityValue` (the spoken readout); trailing monospaced readout, hidden from AX. NEVER `minimumValueLabel`/`maximumValueLabel`: they publish tiny step buttons (`tiny-hit-target`). Radio `Picker`s keep one `AXRadioGroup` and lay their options out in a row (`.horizontalRadioGroupLayout()`).
- Destructive actions MUST use titled native confirmation dialogs with destructive roles.
- App styling inside the tabs: kit components, `MeterBar`, the Island showroom (production `MercurySurface`; [recording-island.md](recording-island.md)).
- Ground: `NSGlassEffectView(style: .regular)` behind the tab view (`ConsoleGlassGround`); no app tint. Clear only `NSWindow.isOpaque` + `backgroundColor`. Reduce Transparency → `windowBackgroundColor`. NEVER place text directly on sampled desktop: every tab covers `ConsoleGlassGround` with `Kit.Screen`'s opaque ground, and SwiftUI glass appears only in kit components over it ([Kit](#kit)).
- Settings is one page per section, chosen in a `Kit.Sidebar` of `Kit.SidebarItem`s (`settings.section.<raw>`, the `SettingsSection` raw value) in contract order: Dictation, Audio, Model, Backend (only with the debug panes, `LaunchOptions.showsDebugPanes`), Island, Readiness, Capture, Privacy, Memory, Danger. No General tab. The tab opens on Dictation and NEVER persists the section; below `Kit.Metrics.railBelow` the sidebar folds to its rail, as the Journal's does. Readiness, Capture and Audio carry the worst attention among their readouts (`.critical` for a crit, `.caution` for a warn): Readiness the backend and microphone readouts, Capture the capture and insertion readouts, Audio the mute readout and a saved microphone that is missing. A page (`SettingsPage`, a `Kit.PageColumn` with no bar) opens with `SettingsSection.title` in the display face and `SettingsSection.sentence`, then islands (`SettingsIsland`) of `Kit.SettingRow`s separated by `Kit.Rule`; a row's control is label-hidden and keeps its label as its accessibility label. The Island page holds `ConsoleIslandSection` alone ([recording-island.md](recording-island.md)). Every copy a page offers goes through `SettingsClipboard.copy` and confirms in the tab's toast (`settings.copied`) only after `GeneralPasteboard.copy` succeeded: “Diagnostics copied to clipboard”, “Agent instructions copied to clipboard”, “Install command copied to clipboard”. Memory: the “Keep dictations in memory” toggle (`setMemoryEnabled`), Copy Agent Instructions (`MemoryPages.agentInstructions(root:)`), the Agent skill row's Copy Install Command, the “Sort entries with Jev” toggle and the TypeSafe key row. Danger: Clear History…, Clear Memory… (enabled while memory is on disk or holds entries), Clear Vocabulary…. Clear History's confirmation dialog carries a second destructive button, “Clear History and Memory”, offered on Clear Memory…'s terms, that erases memory too.
- Privacy, after Data handling (Copy Diagnostics, `system.diagnostics.copy`): the “Link dictations to agent sessions” toggle (`system.agent-links.toggle`) calls `setAgentSessionBinding`, never a bare setting write. Below it, Earlier dictations: Link Earlier Dictations (`system.agent.link-earlier`) calls `linkEarlierDictations()` and is disabled while linking is off or a run is reading. Its caption reads “Finds earlier dictations whose exact words reached one omp or Claude Code session on this Mac, and links them to it.” before any run and after a run is cancelled, “Linking…” while a run reads, then the run's `LinkEarlierRun.summary` as it is, never rebuilt in the view ([runtime.md › Link Earlier Dictations](runtime.md#link-earlier-dictations)).
- Agent skill (Copy Install Command, `system.memory.copy-skill-command`) is enabled on Copy Agent Instructions' terms (memory on, or a folder on disk) and never while the app terminates. A press awaits `prepareAgentSkill()`, which writes the skill into the memory folder ([memory.md › Agent skill](memory.md#agent-skill)); only once the file is on disk does it copy `MemoryPages.skillInstallCommand(root:)` and confirm “Install command copied to clipboard” in the page's toast. The caption says to run it once in Terminal, that it links one skill into the omp, Claude Code and Codex skill folders that exist so every agent learns where the dictations are kept, that Voiceour writes only inside its own folder, that agents may ask before they read outside the project, and that a project with an omp includeSkills list must add voiceour-memory. A failed write copies nothing and turns the caption red: “The skill could not be written on this Mac.”; the next press restores it.
- “Sort entries with Jev” (`system.organizer.toggle`) calls `setOrganizerEnabled`, never a bare setting write, so turning it off cancels every labelling task. Its caption states what is sent, to whom, and that Jev returns labels only and writes no text. It is disabled while it is off and no key is set, and stays operable while on, so an “on” can always be turned off.
- The TypeSafe key row (`system.organizer.key`, a container element around the whole row) shows where the key comes from and NEVER the key (`system.organizer.key.status`: “From the TYPESAFE_API_KEY environment variable”, “Saved in typesafe.key” or “Not set”). A `SecureField` (`system.organizer.key.field`) and Save Key (`system.organizer.key.save`, disabled while the field is blank) call `saveTypeSafeKey`; the field empties when the save succeeds. Remove Key (`system.organizer.key.remove`, only while the key comes from the file) sits behind a titled destructive confirmation. A failed write turns the caption red: “The key file could not be changed on this Mac.”
- Home/Settings MUST share `ConsoleReadiness` values, sentences, remediation; both draw a readout's word as a `Kit.Mark` toned by `Kit.Mark.Tone(_:)` from its `ConsoleReadout.Severity`. `DictationPolicy.owesFirstRunGuidance` = `Settings.hasCompletedFirstRun == false` AND both durable records empty; missing flag defaults false. `completeFirstRun()` stays outside the journaling branch: secure delivery and a saved note complete onboarding; refusal/cancel/failed decode does not.
- All showing routes MUST use `ConsolePresentation`: menu (Open Console and the Report's thread line), `--show-console`, `applicationShouldHandleReopen` (Dock, `open -a`, reopening), `onAppear`. Console open → `.regular`, front/deminiaturized; close → `.accessory`. `--no-activate` or `.prohibited` → no presentation management. Disable miniaturization and restoration.
- Thread route: `coordinator.pendingJournalThread` (an `AgentSessionKey`) asks the console to show one thread. When it is non-nil, on appear and on change, the window selects the Journal tab and the Journal tab selects that thread in Threads through `JournalNavigation.openThread`, then sets the request to nil. This holds whether the console was already open or opens because of the request; a key with no matching thread lands on Threads with its newest thread selected.

## Glossary

The Glossary tab shows the spellings dictation is held to, the spoken forms that reach them, and the corrections the last dictation suggested. What a term is, what an edit, an import or a suggestion may change, and what the editors offer belong to [text-pipeline.md › Glossary rules](text-pipeline.md#glossary-rules). Views: `ConsoleGlossaryTab.swift` (tab, `GlossaryShelf`) and `ConsoleTermEditor.swift`, the editor Timeline's teach (`ConsoleTeachHost`) also renders.

- The tab draws `Kit.Screen` and holds a `Kit.Sidebar` beside a `Kit.Split` (list column, page column), with the Journal's insets and rail rule. The sidebar lists All Terms (`glossary.origin.all`, every live term counted), then one item per origin that holds a live term (`GlossaryQuery.originFacets`), with its count: Yours (`glossary.origin.yours`) and Built-in (`glossary.origin.builtin`). An origin that holds no term is not listed, and a selected origin whose last term goes returns the sidebar to All Terms. While a suggestion is pending and not ignored, the heading “From your last dictation” (hidden on the rail) and Suggestions (`glossary.suggestions`, with its count) follow. On every appear the tab opens on Suggestions, the first one selected, while any are pending; otherwise it keeps its choice. Tombstoned terms are not live and never listed.
- List: “Glossary”, subtitled “N terms” (“1 term”), “M of N terms match” while a query or an origin narrows it, or “N suggestions” (“1 suggestion”) on Suggestions. Its bar holds the search field (`glossary.search.field`, “Search terms and spoken forms”, clear `glossary.search.clear`; Return selects the first match and focuses the list), then Add Term (`glossary.add-term`) and Import… (`glossary.import`, help “Import a newline- or JSON-array word list. Terms stay on this Mac, and duplicates are merged.”) as glyph-only kit buttons that keep their titles as their accessibility labels. A failed import's reason shows as a crimson caption under the bar until the next import or search edit. A query typed on Suggestions switches to All Terms. A query that matches nothing shows one unavailable view, “Nothing matches “<query>””, with Clear Search, plus Show All Terms while an origin narrows the list. ↑ and ↓ move the selection once the list holds focus; a row press focuses the list.
- Term rows are `Kit.TitleRow`s (`glossary.term.<termId>`, tooltip the canonical): the canonical spelling in the code face (`monospacedTitle`, `TextRole.code`) over “Heard as a · b” or “Matched by its spelling only”, and a BUILT-IN mark on a bundled term. VoiceOver label: “<canonical>, heard as a, b” or “<canonical>, matched by its spelling only”. Context menu: Remove Term…. Suggestion rows (`glossary.suggestion.<id>`) read “<misheard> → <canonical>” in the code face over “Suggested correction”, VoiceOver label “Suggested correction: <misheard> becomes <canonical>”.
- Term page: the bar holds Remove Term… (`glossary.term.remove`, destructive, help “Remove this term from the glossary”) behind the titled destructive confirmation “Remove this term?” — “Dictation stops holding “<canonical>” to this spelling. Text you already pasted is not affected.” The header carries the origin as eyebrow, the canonical as title in the code face (`monospacedTitle`, `TextRole.codeTitle`) and the heard-as summary; then a “Spelling and spoken forms” island holds `ConsoleTermEditor` (prefix `glossary.term`, Save `glossary.term.save`, enabled only for a non-blank change), reseeded from the stored term after a save. Remove writes `settings.glossary` and calls `saveSettings()`. Nothing selected → “No term selected”, described “Click a term to edit it. Case and spacing variants of a term are matched automatically.”
- Add Term opens the “New term” page: the same island, prefix `glossary.draft`, Save `glossary.draft.save`. A spelling that is already a term is refused (““<canonical>” is already a term. Open it to add a spoken form.”). A saved draft selects the new term, on All Terms when Built-in was selected. Pressing a row ends the draft.
- Suggestion page: the bar holds Teach (`suggestion.<id>.accept`, primary, `acceptSuggestion`, label “Teach correction from <misheard> to <canonical>”), Ignore (`suggestion.<id>.ignore`, label “Ignore suggestion for <misheard>”; hides it while it stays pending and teaches nothing) and Never Suggest This (`suggestion.<id>.reject`, `rejectSuggestion`, help “Never offer this correction again. The pasted text is unchanged.”). The header reads “From your last dictation”, the canonical and “Heard as <misheard>”; a “Suggested correction” island shows the pair, as one element labelled like its row, and the caption “Accept teaches future dictation only — the text you already pasted is never changed.” An answer selects the next pending suggestion, else the previous; the last one answered returns the sidebar to All Terms, on the taught term after Teach and on nothing after Ignore or Never Suggest This. A refused Teach keeps the page.
- A successful import confirms in the page's toast (`glossary.imported`): “Imported 1 term” or “Imported N terms”.
- No live term, no draft and no suggestion → one unavailable view in place of the whole tab, sidebar included: “No terms yet” — “A term is the spelling Voiceour holds a word to when dictation keeps hearing it wrong. Add one, or import a word list.” — with Add Term (primary, `glossary.add-term`), Import… and the failure caption.
- Derived lists (matches, origin facets, the live count, the open term's forms and derived variants, visible suggestions) MUST be cached in state and rebuilt on appear and on change of the glossary, the pending suggestions, the query or the sidebar choice, NEVER in `body`.

## Journal

History is the record: the newest 500 dictations delivered to non-secure targets, stored in `recent-sessions.json`, cleared by Clear History. Memory is the durable, uncapped record in `<support>/memory/` ([memory.md](memory.md)), and the only one that holds notes and topics. The Journal tab shows both through five lenses, built from the [Kit](#kit). Views: `ConsoleJournalTab.swift` (tab, `JournalSidebar`), `JournalTimelineLens.swift` (with `ConsoleTeachHost.swift`), `JournalRewindLens.swift`, `JournalThreadsLens.swift`, `JournalTopicsLens.swift`, `JournalNotesLens.swift`, `JournalEntryRow.swift`, `JournalAgentNotes.swift`; pure grouping lives in `Sources/VoiceCore/Journal.swift` (`JournalQuery`).

- The tab draws `Kit.Screen` and holds `JournalSidebar`, a `Kit.Sidebar`, beside one lens. The sidebar lists one `Kit.SidebarItem` per lens (`journal.lens.<lens>`), in `JournalLens.allCases` order — Timeline, Rewind, Threads, Topics, Notes — with what it holds (History rows, threads, topics, notes; Rewind shows none), then “Recent Threads” (a `Kit.SidebarHeading`): the five threads with the newest entries (`journal.sidebar.thread`), each a plain button led by the agent's mini `Kit.Badge`, with a warning glyph while one of its dictations was not sent, whose accessibility element combines its children and keeps the press; a press calls `JournalNavigation.openThread`. While the tab is narrower than `Kit.Metrics.railBelow` (1,000 pt), as a window the user narrowed stays across launches, the sidebar folds to a rail of glyphs (`Kit.Metrics.railWidth`) without Recent Threads, each item keeping its name and count as its label, value and tooltip. The tab opens on Timeline unless a thread route is pending ([Console](#console)); NEVER persist the lens. `RenderOverrides.journalInitialLens`, `journalInitialDay` and `journalInitialThread` pin a lens state for the harness.
- Every lens is a `Kit.Split`: a list column (`Kit.ListColumn`, titled with the lens's name and subtitled with its count) beside a page column (`Kit.PageColumn`) that shows the selected item. A row press selects its item and gives the list focus; a press on the selected row keeps it; ↑ and ↓ move the selection once the list holds focus and scroll the row into view. With nothing selected and a non-empty list, a lens selects its first row (Timeline keeps its own rule, below). When the selected item disappears, the item that took its place in the list is selected, else the one before it, else nothing. A search that hides the selection leaves its page on screen. A lens with nothing at all shows one unavailable view in place of both columns.
- Every group of content on a page — the transcript, its folds, the teach editor, Highlights, a block, the agent notes, Dictations, Entries, Details, a creation or edit form, a note's text — sits in a `Kit.Island`, headed by its `Kit.SectionTitle` inside when the group has a heading. The page header and Rewind's figures sit on the screen's ground.
- Timeline reads History's rows. Rewind, Threads, Topics and Notes read `coordinator.journalEntries`: every memory entry plus each History row memory does not hold, oldest first, memory winning for an id both hold. A lens NEVER stores anything of its own: topic edits and filing go through the coordinator into memory, and the only network request a lens can lead to is Sort Entries ([memory.md › Sorting](memory.md#sorting)).
- Derived lists (entries, days, blocks, threads, topic pages, matches) MUST be rebuilt on appear, on change of History's row ids or bindings, and on change of `coordinator.memoryRevision` (Topics also on `coordinator.memoryTopics`), NEVER in `body`.
- Rewind, Threads, Topics and Notes MUST take the calendar from `RenderOverrides.calendar ?? .current` and render month and weekday names from fixed arrays, so goldens never depend on the locale.
- A copy a page offers confirms in the lens's toast (`Kit.Flash`; `sessions.detail.copied`, `journal.rewind.copied`, `journal.threads.copied`, `journal.topics.copied`, `journal.notes.copied`), in the sentence VoiceOver hears, and only after `GeneralPasteboard.copy` succeeded. A reading row confirms its own copy ([Reading rows](#reading-rows)).

### Timeline

- List: “Timeline”, subtitled “N dictations” (“1 dictation”), or “M of N dictations match” while a query or a filter narrows it. Its bar holds the search field (`sessions.search.field`, “Search dictations”, clear `sessions.search.clear`; Return selects the first match and focuses the list) and, only while some row has a delivery target, the app filter (`sessions.filter`, a glyph-only glass menu, help “Show dictations from one app”, holding an inline `Picker`: All Apps, then “<label> (<count>)”); under them, one `Kit.FilterChip` per filter in force: the app (clear `sessions.app-filter.clear`, “Show all apps”) and the agent session, named by `displayTitle` (clear `sessions.agent-filter.clear`, “Show all agent sessions”).
- Search, app filter and agent-session filter are ANDed; the agent-session filter keys on `agentSession?.key`. Facets: count descending, display label, bundle id; app name from newest row. Last matching app row disappears → drop filter; same for the agent-session filter's last bound row. The menu re-sorts resolved labels; `RecentSessionQuery.appFacets` preserves its pure order.
- Rows, grouped by day under `Kit.GroupHeader`s with the day's count, are `Kit.PreviewRow`s: stamp, muted glyph, destination icon and name, outcome mark (PASTED, COPY ONLY or FAILED), NOT SENT mark when the bound session never sent the dictation (`AgentSessionBinding.isNotSent`), then a two-line preview. The name is the app's, except on a row bound to an agent session, which names its thread instead: `AgentSessionBinding.displayTitle` (“<Agent> · <title>”, else “<Agent> · <folder name>”, else “<Agent> session”), beside the app's icon, because every bound row went to the same terminal. The row's VoiceOver label says the same: stamp, outcome, NOT SENT when it shows, “to <destination>”, word count, muted when it was, then the preview.
- Selection: the first visit selects the newest row unless `RenderOverrides.historyStartsDeselected`; after that only the reader moves it, and a reload never reselects what the reader left. Nothing selected → “No dictation selected”.
- Page bar: Copy (`sessions.detail.copy`, primary), Fix / Teach (`sessions.detail.teach`, ⌘T), Open Thread (`sessions.detail.thread`, bound rows) and More (`sessions.detail.more`): Show Only *App*, Show Only This Agent Session, Copy Resume Command (only when `AgentSessionBinding.resumable`), Unlink from Thread, Delete Transcript…. Header: the day and time, then the thread's `displayTitle`, else the app's label, else “Dictation”, then the word count (after “Pasted into <app>” on a bound row), then the outcome mark, a non-normal safety mark, NOT SENT and the muted glyph.
- The transcript island holds `SelectableTranscriptText` at 15 pt (`sessions.detail.transcript`, label “Transcript”, value “<n words>, recorded <detail stamp>”, named actions “Copy transcript” and “Teach a correction”). Its height is measured on a scratch layout at the width SwiftUI proposes, and the live text view keeps its text container at the width it is placed at, so the drawn lines always fill exactly the height reserved for them; measuring NEVER resizes the live view. A single click copies all delivered text as a plain, non-transient string (“Transcript copied to clipboard”). Selection or right-click `Fix / Teach “word”`, then ⌘T or Fix / Teach, teaches. One caption under the island names the selected teaching surface or the instruction; the teach editor (`ConsoleTeachHost`) opens in an island under it.
- Sent (only when the bound session's sent prompt differs from the delivered text: `AgentSessionBinding.sentText != nil`, `sessions.detail.sent`), Raw (only when different, `sessions.detail.raw`) and Details (`sessions.detail.details`) MUST be sibling `Kit.Disclosure`s in one island, independent, all closed on each newly selected row. Details: Target (friendly app + non-normal safety mark), Agent (`displayTitle`, `sessions.detail.agent`, + monospaced `locationLine`, with ` · Not sent` appended when `isNotSent`; no send wording while pending; for evidence `words`, a secondary line `Linked by its words`, `sessions.detail.evidence`; on an unbound row with `unlinked`, one plain secondary line `Not linked. <sentence>` instead, `sessions.detail.unlinked`, sentences in [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)), Timings, least-sure word. No evidence → omit Details; a miss is evidence.
- Row context menu: Copy Transcript, Fix / Teach a Word, Show Only *App*, then — on an agent-bound row — Open Thread, Show Only This Agent Session, only when resumable Copy Resume Command (`AgentSessionBinding.resumeCommand`, shell-quoted), and Unlink from Thread (`unlinkThread(rowID:)`: no confirmation; the row keeps its text and shows `Not linked. You removed this link.`, and nothing links it again), Delete Transcript…, behind the titled destructive confirmation “Delete this transcript?”.
- Words: a row is a dictation, never a session. No row → unavailable view “No dictations yet”; a failed delete reads “Could not delete this dictation — it is still on disk. Try again.”
- Timeline reloads derived rows when any row's `agentSession` changes, and calls `refreshAgentSessions()` on appear, when the set of row ids changes, and on selection ([runtime.md › Agent session binding](runtime.md#agent-session-binding)). It keeps every `sessions.*` identifier.

### Rewind

- List: “Rewind”, subtitled “N days”. Every day that holds an entry, newest first, grouped by month (“June 2025”) as `Kit.TitleRow`s (`journal.rewind.day-row`): “Sunday, Jun 15” over “3 entries · 37 words · 2 apps”. The selected day is seeded from `RenderOverrides.journalInitialDay`, else the newest day; a day that loses its entries passes the selection to the next older day, else the next newer.
- Search field `journal.rewind.search` (“Search everything you said”, clear `journal.rewind.search.clear`) turns the list into matches from every day: text, session title, project folder, app name; newest first under day headers, at most 200 shown, the count in the subtitle (“4 matches”, “1 match”, “Showing the newest 200 of N matches”). A match press selects its day and marks that entry on the page, scrolled into view; the page keeps showing the selected day while the search runs. A search shows entries only, never an agent note.
- Page bar: Earlier Day (`journal.rewind.earlier`) and Later Day (`journal.rewind.later`), which step only through days that hold entries and are disabled at the ends, then Copy Recap Prompt (`journal.rewind.recap-prompt`, primary), only when the selected day holds at least one entry memory keeps.
- The page names the day, then its figures as `Kit.MetricTile`s two to a row: Entries (count and words; `journal.rewind.entries`, AX value “<count> · <n> words”), Speaking time (only when measured), Where (agent sessions, apps, notes), Span (first to last time). With the recap prompt, a caption: “Paste it into your coding agent. The agent reads this day in the memory folder and saves a recap there.”
- Highlights: when the day has a confident label, a “Highlights” section lists the day's decision, idea, to-do and question entries in time order (`RewindDay.highlights`, kind confidence ≥ `JournalQuery.highlightConfidence`). Then, when agents saved notes for the day, “From your agents” ([Agent notes](#agent-notes)).
- Then one section per block, in time order. A block is a run of consecutive entries on one subject: the same agent session, the same app when no session is bound, or notes with no session (“Notes”); a pause longer than 30 minutes starts a new block. A subject that returns later in the day is marked “continued”. A session block carries Open Thread beside its heading, and its session title has a context menu: Open Thread and, only when resumable, Copy Resume Command.

### Threads

- Agent sessions grouped by working directory: the folder's name is the heading; sessions with no known directory sit under “No project folder”, last. List: “Threads”, subtitled “N agent sessions”, or “N of M agent sessions match” while searching. A thread row (`journal.threads.row`, a `Kit.TitleRow` with the agent badge) shows title, then agent, dictation count and time span, and a “<n> NOT SENT” mark; its VoiceOver label adds the not-sent count to the same facts, and its named action is “Open thread”. The title is the session's own title, else its project folder's name, else “<Agent> session”, never an id prefix; the row, the sidebar and the page read the same one (`JournalThreadsLens.title(of:)`). Memory's thread pages keep `JournalThread.displayTitle`, whose bare-thread fallback ends with the id's first 8 characters, because an agent finds its own page by its id.
- Selection is the tab's `openThread`, so another lens, the sidebar or the menu's thread route can select a thread; when it names no listed thread, the newest one is selected.
- Page bar: Copy Resume Command (`journal.threads.resume`, primary, resumable sessions only), Show in Timeline (`journal.threads.timeline`, only while one of the thread's entries is in History; sets Timeline's agent-session filter), Copy Outcome Prompt (`journal.threads.outcome-prompt`, only when memory keeps one of the thread's entries, so its thread page exists).
- The page names the agent and folder, the title, and “<n> dictations · <span>” with “<k> not sent” when any were not. Then “From the session” ([Agent notes](#agent-notes)), or, when no agent note names the thread and the outcome prompt is offered, an island saying no outcome is recorded yet and that Copy Outcome Prompt asks the session's agent for it; then “Dictations”, every one oldest first under day captions; then a Details `Kit.Disclosure` (`journal.threads.details`) holding Session id (`journal.threads.session`) and Folder (`journal.threads.folder`, when known), closed whenever another thread is selected.
- Search field `journal.threads.search` (clear `journal.threads.search.clear`) filters threads by the same fields as Rewind; nothing matching shows an unavailable view whose Clear Search is `journal.threads.nomatch.clear`.
- No thread → unavailable view “No agent sessions yet”, whose description reads the setting. Linking off: “Turn on Link dictations to agent sessions in Settings ▸ Privacy. A dictation that you paste into Tern then joins its session here.” Linking on: “Paste a dictation into an omp or Claude Code pane in Tern.”

### Topics

- Topics are the user's ([memory.md › Topics](memory.md#topics)). List: “Topics”, subtitled “N topics”. New Topic (`journal.topics.new`) opens a “New Topic” island at the head of the list, which shows on its own while there is no topic: Name (`journal.topics.new.name`), “What belongs here, in one line” (`journal.topics.new.summary`) and Add Topic (`journal.topics.add`, disabled while the name is blank). A refusal shows as a red caption under the button (`journal.topics.new.refusal`) in words that say what to change. Adding a topic selects it and closes the island.
- A “Sorting” island, only while `settings.organizerEnabled` and a key is set: Sort Entries (`journal.topics.sort`, `sortEntries()`), replaced by Stop Sorting (`journal.topics.sort.stop`, `cancelSortEntries()`) while a run is in flight, and a caption (`journal.topics.sort.status`) from `organizerRun`: what the run does before any run, “Sorting <done> of <total>…” during one, “Sorted <n> entries.” after one, plus “<failed> could not be sorted.” when any failed.
- Rows: every topic, most entries first, then by name compared case- and diacritic-insensitively without the locale, then by id. A row (`journal.topics.row`, a `Kit.TitleRow`) shows the name and “<n> entries · <summary>” (summary omitted when empty); its VoiceOver label reads “<name>, <n> entries, <summary>” and its named action is “Open topic”. A topic with nothing filed still has a row.
- Page bar: Copy Synthesis Prompt (`journal.topics.synthesis-prompt`, primary) and Delete Topic… (`journal.topics.delete`) behind the titled destructive confirmation “Delete this topic?” — “Its entries stay in memory and become unfiled.”
- The page names the topic and its summary, then “From your agents” when agents saved notes whose `topic` is this topic's id ([Agent notes](#agent-notes)), then “Entries”, newest first under day captions, as `JournalEntryRow`s, then “Name and summary”: Name (`journal.topics.name`) and Summary (`journal.topics.summary`) fields and Save (`journal.topics.save`, enabled only when the trimmed fields differ from the topic; a refusal shows in `journal.topics.refusal`).
- No topics: the “New Topic” island, and a page that says to name a topic and file entries from their menu.

### Notes

- Every `.note` entry, newest first (equal times by id), grouped under `SessionsFormatters.dayHeader` headers. Day groups are cached in state and rebuilt on appear and on change of the entries or the query, NEVER in `body`. List: “Notes”, subtitled “N notes”, or “N of M notes match” while searching.
- The list's bar holds “Take a Note” (`journal.notes.take`, primary) that calls `startNote()`; while the note it started records (`.recording` with `captureIntent == .note`) it reads “Finish Note” and calls `stopAndProcess()`. It is disabled while any other dictation is recording or processing. A caption under the list names the spoken command and says a note is pasted nowhere.
- With at least one note: search field `journal.notes.search` (clear `journal.notes.search.clear`) over every note's text and agent session (`JournalQuery.matches`), on every day at once. A query that matches nothing shows one unavailable view whose Clear Search button is `journal.notes.no-matches.clear`. With no note at all: an unavailable view that names the menu, this lens and the spoken command, with Take a Note.
- Rows are `Kit.PreviewRow`s whose VoiceOver label reads “<time>, note, [not sent, ][<kind>, ]<text>”, with a context menu: Copy Text, Open Thread (note has a session), File Under, Delete Entry….
- Page bar: Copy (`journal.notes.copy`, primary, “Note copied to clipboard”), File Under (`journal.entry.file`), Open Thread (`journal.notes.thread`, note has a session) and Delete… (`journal.notes.delete`) behind the titled destructive confirmation “Delete this entry?”; a failed delete reads “The entry could not be deleted.” (`journal.entry.delete-error`). The page names the day and time, “Note”, and the session's title or “Saved to memory. Nothing was pasted or copied.”, with the note's marks, then its whole text in an island, selectable.

### Agent notes

- Agent notes are the Markdown files agents saved under memory's `agents/`; what counts as one, and the limits, belong to [memory.md › Agent access](memory.md#agent-access). `ConsoleJournalTab` calls `refreshAgentNotes()` when the tab appears, when the lens changes and when a thread is selected, including when another thread replaces the selected one, and passes `coordinator.agentNotes` and `coordinator.memoryStore.root` to Rewind, Threads and Topics. NEVER load them in `body`; the coordinator loads them off the main actor.
- Per note, one `JournalAgentNoteRow` (`journal.rewind.agent-note` in Rewind, `journal.threads.agent-note` on a thread's page, `journal.topics.agent-note` on a topic's page): a plain row inside its section's island, ruled off from the next note by a `Kit.Rule`, drawing no surface of its own: the `sparkles` `Kit.Badge`, a caption reading “<title> · by <author> · YYYY-MM-DD HH:mm”, the title being the file name when the note has none and the time the file's modification time in the lens calendar, then the body. Rewind's “From your agents” shows the notes whose `day` is the selected day; a topic's “From your agents” shows the notes whose `topic` is its id; a thread's “From the session” shows the notes whose `session` equals the thread's file stem (`MemoryPages.threadFileStem`), newest modification first, and the Threads lens picks them again whenever the selected thread or the loaded notes change. No matching note → no section.
- The body is plain, selectable text: NEVER rendered as Markdown, a link or an attributed string, NEVER executed or opened. At most 4,000 characters show; a longer body is cut there and ends with “…”. An agent note is not a `JournalEntryRow` and is never one of the user's entries: no copy on click, no context menu, no File Under or Delete Entry…, no search match, no day figure or count.
- Copy Recap Prompt, Copy Synthesis Prompt and Copy Outcome Prompt (`JournalPromptCopyButton`) copy `MemoryPages.recapPrompt(day:root:calendar:)`, `MemoryPages.synthesisPrompt(topic:root:)` and `MemoryPages.outcomePrompt(thread:day:root:calendar:)` with `GeneralPasteboard.copy` and confirm in the page's toast: “Recap prompt copied to clipboard”, “Synthesis prompt copied to clipboard” or “Outcome prompt copied to clipboard”; a refused clipboard write shows and says nothing. Recap requires an entry memory keeps on that day (`memoryIDs`, the ids in `coordinator.memoryEntries`), because the day page the prompt names exists only then. Copy Outcome Prompt names the day of the thread's latest entry in the planner calendar (`DictationCoordinator.memoryCalendar`, in the lens calendar's zone). Voiceour calls no writing model: the prompt goes to the user's own agent, which saves its note under `agents/`.

### Reading rows

- Rewind, Threads and Topics pages render entries as `JournalEntryRow`: timestamp gutter + the whole text, NEVER truncated, marks closing the first line. The row is the control: a click copies the text as a plain, non-transient string; a transient COPIED mark in the gutter + VoiceOver confirmation. A Rewind search match's row is lit as selected (`Kit.RowButtonStyle`).
- NOTE mark on a note; NOT SENT mark when the bound session never sent the dictation; a kind mark (IDEA, DECISION, TO-DO or QUESTION) when the entry's label names that kind with confidence ≥ `JournalQuery.highlightConfidence`, the bar Rewind's Highlights use (`JournalEntryRow.highlightKind(of:)`). All are words, and VoiceOver reads them before the text.
- Context menu: Copy Text; Show in Timeline (row still in History); Open Thread (row has a session); File Under; Delete Entry… only when History does not hold the entry (every note), behind a titled confirmation dialog with a destructive role, deleting the memory entry with that id. Teach, Raw, Sent and Details stay in Timeline, and so does Delete for a row History holds; NEVER add them to a reading row.
- File Under (`JournalFileUnderItems`, and `JournalFileUnderChoices` inside a page's glass menu): one item per topic in memory's order, the entry's effective topic checked, then No Topic; choosing calls `fileEntry(id:underTopic:)`. With no topics it holds one disabled item, “No topics yet”.

### App identity

- `AppIdentity`: installed Finder display name > persisted name > `AppDisplayName.label(bundleId:name:)`; bundle id stays key, never display label. Icon: Home's top-app rows `Kit.AppBadge` (monogram if uninstalled), Timeline rows `Kit.AppLabel`; Target and the app filter chip have names only.
- `InstalledAppCatalog`: sole bundle-id LaunchServices lookup, main-actor/process-lifetime cached. `RenderOverrides.installedApps` pins goldens. The live menu's *Will paste into <app>* and *Will copy for <app>* (no class name) and the Report's outcome detail use `AppDisplayName` directly.

## Kit

The component kit is `Sources/Voiceour/Kit*.swift` (`KitTokens`, `KitSurfaces`, `KitLayout`, `KitControls`, `KitRows`, `KitContent`, `KitHome`), every component under the `Kit` namespace. Every console tab is built from it; `console.kit.gallery` and `a11y.kit.reduce-transparency` render every component in a console composition — sidebar, list, page, islands — except `Kit.Hero`, which Home's scenes show ([ui-harness.md › Scenes](ui-harness.md#scenes)).

- Two layers. Content — figures, rows, transcripts, preferences — sits in app-painted islands (`Kit.Island`) on `Kit.Screen`'s fixed-dark ground, in the app palette. Navigation and controls — the sidebar panel, search fields, filter chips, action and menu buttons, the toast — are Liquid Glass above it. Content is NEVER glass. Kit text goes through `.roleStyle(_:)` (`TextRole`) and every painted surface under text declares `\.surfaceGround`, so the contrast lint measures what the reader sees. `Text.roleStyle(_:).foregroundStyle(_:)` renders the colour it records: `RoleStyledText` applies the colour once, because `Text` keeps the first foreground it is given; a non-`Text` label takes `.roleStyle(_:color:)`.
- SwiftUI glass (`.glassEffect`, `GlassEffectContainer`, `.glassBackgroundEffect`, the `.glass` and `.glassProminent` button styles) appears only inside kit files (`.omp/rules/no-swiftui-glass.md`); every other view composes kit components. Kit glass samples `Kit.Screen`'s ground or content scrolling under it, NEVER `ConsoleGlassGround`: glass cannot sample glass. Neighbouring glass controls sit in one `Kit.GlassGroup` (one `GlassEffectContainer`) so they sample one region. Islands are painted, not glass, for the same reason.
- Reduce Transparency (system or harness pin, through `A11y`) replaces every kit glass surface with `controlBackgroundColor` and a drawn rim, the glass button styles with `.bordered` / `.borderedProminent`, every island with flat `Ink.surface` and a `lineEdge` rim, and a selected row's pane with `Ink.surface` under its rim, and it drops the dot grid. Increase Contrast escalates washes, rules, the island's specular rim, mark fills and the selected row's rim; Differentiate Without Color adds a mark's symbol; Reduce Motion drops every kit animation (`Kit.Motion`).
- Measures (`Kit.Metrics`): sidebar 206 pt, list column 344 pt, page column the rest with a 720 pt reading measure and 32 pt margins, so at the 1164 pt minimum, inside the tab view's 3 pt insets, the page is 592 pt, on the 4 pt grid; every glass control 28 pt (`.controlSize(.large)` with its glyph in a 16 pt box, which a tall symbol would otherwise push to 30); toast 32 pt; preview rows 64 pt, title rows 44 pt, sidebar items 32 pt; a reading row is 32 pt on one line and 44 pt on two. Islands: radius 20 pt, padding 16 pt (`islandRadius`, `islandPadding`). Marks: 20 pt compact, 24 pt regular (`markHeight`, `markHeightRegular`). Badges: 32 / 22 / 18 pt discs. The dot grid's pitch: 24 pt (`dotPitch`). The list rule overlays the list's edge so the page keeps a whole-point width.
- Selection is the lit row every list and sidebar in the console uses (`Kit.RowButtonStyle`): the `Ink.pane` fill, a specular hairline and a 1 pt `Alien.bloom` rim (1.5 pt under Increase Contrast), plus the `.isSelected` trait; hover and press are `Plate.hover` / `Plate.pressed` washes.
- Layout: `Kit.Split` (list column, page column); `Kit.ListColumn` (title in the 28 pt light mono display face, count subtitle, a bar, then a lazy stack of rows with pinned `Kit.GroupHeader`s, which paint `Ink.void`; arrow keys move the selection once the list holds focus, and `reveal` scrolls a row into view); `Kit.PageColumn` (a trailing glass bar over a centred reading measure that scrolls under it; `identity` restarts the scroll per item). The list header stands above its rows and the page bar holds glass only, because the scroll edge effect that keeps text legible over moving content renders offscreen as an opaque white sheet; the kit hides it.
- Controls: `Kit.SearchField` (Escape clears, its clear button labelled “Clear search”), `Kit.ActionButton` (at most one `.primary` per bar), `Kit.MenuButton` (requires an identifier: a bare-symbol menu otherwise publishes the symbol's name), `Kit.FilterChip`, `Kit.Disclosure` (a button heading whose AX value reads “Expanded” or “Collapsed”), `Kit.RowButtonStyle`. `Kit.SidebarItem`: a glyph (signal green when selected), a name, an optional count and an optional `attention` (`.caution` an amber triangle, `.critical` a crimson octagon, trailing; a corner badge on the rail); a plain button whose accessibility element combines its children and keeps the press, labelled by the name, valued by the count then “needs attention” (“3, needs attention”, or “needs attention” with no count). `Kit.Sidebar`: a `Kit.GlassPanel` holding a column of items and headings. `Kit.SidebarHeading`: a header-trait heading over the items it groups; a rule with the name as its tooltip on the rail. `Kit.SettingRow`: one preference in an island, its title leading and its control trailing on the title's line, its caption under both (in `captionColor` when the words already say a state); the caption is a sibling of the control, never its label. Under the `kitCompactControls` environment value an action button, a menu button and a sidebar item draw their glyph alone and keep their title as their accessibility label; `Kit.PageColumn` sets it on its bar when the titles do not fit the page's width (`ViewThatFits`), every tab with a sidebar sets it on the sidebar's rail, and the Glossary's list bar always sets it.
- Content: `Kit.Screen` (the `Ink.void` ground and a dot grid hidden under Reduce Transparency and from VoiceOver; the ground ignores the safe area, the content does not; the dark colour scheme for everything inside; declares `Ink.void` as its ground), `Kit.Island` (Home's pane: void at 55 %, `Ink.pane` and `glassTint`, the neon `Alien.bloomGlow` rim, the white specular rim, an inner dark hairline, two soft shadows; `glow: false` drops the neon rim alone; `.kitIslandSurface(cornerRadius:glow:elevated:)` paints the same surface, `Kit.IslandSurface`, behind any view), `Kit.Hero` (64 pt thin mono, a heading), `Kit.StatTile` (badge, mono figure and unit, caption; one AX element labelled by the caption and valued by the figure), `Kit.Figure` (20 pt mono figure over its label; one AX element), `Kit.MeterRow` (leading badge, title over a share `MeterBar`, figure over caption; one AX element labelled by the title, valued by `accessibilityValue`), `Kit.AppBadge` (the app's icon, else its initial in a disc; hidden from VoiceOver), `Kit.Badge` (an SF Symbol in `Alien.bloom` on a ringed disc, `.regular`, `.small` or `.mini`; hidden from VoiceOver), `Kit.Mark` (below), `Kit.MetricTile` (a small island tile without the neon rim or shadows; AX label is the label, AX value “value · detail”), `Kit.Fact`, `Kit.AppLabel`, `Kit.PreviewRow` (meta line and marks over two lines of words, one AX element its caller names), `Kit.TitleRow` (a name over one line of facts, leading badge, trailing marks; `monospacedTitle` sets the name in the code face), `Kit.PageHeader` (eyebrow, title, subtitle, accessory; `monospacedTitle` sets the title in the code title face), `Kit.SectionTitle` (an island's heading, as Home's “Top apps”, with an optional trailing control), `Kit.Rule`.
- `Kit.Mark` is the one state mark everywhere — the console, Settings, Home's first-run card, the menu: the word uppercased in the micro mono voice, in its tone's app-palette hue on a capsule tinted with it (8 %, 18 % under Increase Contrast), no rim. Tones: `.neutral` (the quieter text step on `Plate.rest`), `.success` mint, `.caution` amber, `.critical` crimson, `.info` and `.live` cyan; `Kit.Mark.Tone(_:)` maps a `ConsoleReadout.Severity`. Sizes: `.compact` 20 pt, `.regular` 24 pt. Inside a disabled group the word drops to the lowest text step on a neutral plate. One static-text AX element whose label and value are the word as shown; never selectable.
- Confirmation: `Kit.Flash` holds one message at a time for 1.4 s and announces it to VoiceOver; `.kitToast(_:identifier:)` shows it as `Kit.Toast` along the page's bottom edge. A caller shows a message only after the write it reports succeeded.

## Visual vocabulary

`DesignTokens.swift` owns values. The app palette paints every console tab's content, the menu and the island; native controls keep system semantic colours.

| token / role | contract |
| --- | --- |
| `Ink.void` | opaque sRGB (0.02, 0.03, 0.05) |
| `Text.high`, `Text.mid`, `Text.low` | (0.89, 0.91, 0.95); (0.64, 0.71, 0.80); (0.51, 0.56, 0.64) |
| cyan / mint / amber / crimson | active-live-focus / success / degraded-waiting / failure-destructive |
| `micro`, `caption`, `label` | 10 / 12 / 13 pt |
| `tileValue`, `metric`, `heroMetric` | 20 / 32 / 64 pt |
| `hair`, `xs`, `sm`, `md`, `lg`, `xl` | 2 / 4 / 8 / 12 / 16 / 24 pt |
| controls | 24 / 28 / 32 / 40 pt; compact status marks: 20 pt |

- One dominant signal colour/view. `Alien.bloom` is the one signal colour — glyph discs (`Kit.Badge`), selection rims, a selected sidebar glyph, share meters, the heat grid — NEVER text. Heat ladder: four steps = quartiles of busiest day; Differentiate Without Color substitutes size steps at one hue.
- `OnGlass` cyan/mint/amber/crimson: system-glass text only, ≥4.5:1 against white and black; not painted/opaque grounds.
- `Kit.Island`s — Home's and every console tab's — remain fixed-dark in either appearance. Paint `Ink.pane` + `glassTint` + specular/`Alien` rims; NEVER stack another material over the glass ground. Declare `surfaceGround` for contrast lint.
- `MenuBarExtra(.window)`: 280 pt, three whitespace-separated blocks: Status (state, optional mute, Fn, headline), Report (failure/transcript/outcome; absent when empty), Actions (primary + grouped commands). The status chip is a regular `Kit.Mark` and the mute chip a compact one; each command row leads with a mini `Kit.Badge` glyph. The transcript well wears the island surface and holds only the transcript; a click copies it, and a mint caption under the well confirms the write until the transcript changes. Download/warmup MUST stay visible; re-poll health while acquisition advances.
- Menu outcome: the Report's chip and detail are `InsertionOutcome.summary(in: coordinator.lastDeliveredApp)`; `CaptureModels.swift` holds the exact sentences. PASTED → “Pasted into <app>.” (“Pasted.” when the app is unknown); COPY ONLY → why, in one plain sentence that names the app when it is known, then “Press ⌘V to paste.” (a cancel after the copy: “Cancelled. The text is on the clipboard.”); DELIVERY FAILED → one plain sentence per reason. Every reason `InsertionSafetyPolicy` and `PasteboardInserter` can produce has its own sentence; only an unknown string falls back to the humanized reason. The state name stays `pasteAttempted`, and the island's announcements keep their own words. `lastDeliveredRowID` (nil for a secure target or a note) and `lastDeliveredApp` are set with `lastOutcome` and cleared with it.
- Menu link line: inside Report, never a command row, only when the reported outcome is `.pasteAttempted`, `settings.agentSessionBindingEnabled` is on, and the History row `lastDeliveredRowID` names exists. A bound row shows one borderless button (`menu.report.thread`): `displayTitle` on one tail-truncated line and a trailing secondary `chevron.right`, AX label “Open thread, <displayTitle>”; it sets `pendingJournalThread` and opens the console as Open Console does ([Console](#console)). A row with `unlinked` shows the caption `Not linked. <sentence>` (`menu.report.unlinked`; [runtime.md › Link miss reasons](runtime.md#link-miss-reasons)). Neither → nothing while the link resolves. The line arrives with the menu's report transition, respecting Reduce Motion, and the Actions container keeps its three rows.
- Menu notes: the Actions block's grouped commands carry “Take a Note” (`menu.take-note`, calls `startNote()`) only while no dictation or note is in flight, the menu is not gated (`errorMessage == nil`), and no failure remedy row (Try Again, Open System Settings) shows; the remedy row takes its place so the container keeps three rows. While a note records (`captureIntent == .note`) the Status headline's target line reads “Will save as a note”. A saved note reports as `InsertionOutcomeSummary.noteSaved` from `lastSavedNoteID`, under the gate a delivery outcome uses (no error, nothing in flight): chip “NOTE SAVED”, Report detail “Saved to memory. Nothing was pasted or copied.”; `.noteSaved` itself falls to IDLE with the delivery states.
- Motion: quick 0.14 s, standard 0.18 s, deliberate 0.22 s. MUST respect Reduce Motion. Animate menu report/state resizing; native console keeps system behavior; resting settings stay static except the Island showroom (live only while visible, still under Reduce Motion).
- Controls MUST have stable human labels. NEVER encode state only in colour. Chips/marks carry words; Differentiate Without Color adds symbols. Captions stay separate from control AX labels. Gesture-only behavior requires named AX actions; completion announces.
- `micro` sets only chips, keycaps, the primary capsule and chart axes. NEVER micro subtext: labels, hints or counts beside content; a fact the reader needs takes the caption voice.
